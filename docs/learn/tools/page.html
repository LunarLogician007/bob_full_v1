bob, tool by tool

Volume 3 followed a configuration from the cable into the chip. This volume goes one step earlier: how ./bob build turns Verilog into that configuration in the first place. It follows one design, wide.v, a 12-bit counter and an 8-bit shift register with a few XORs, through every tool, in the order they run.

Press Next (or →) to build each picture. The cells, the truth table, the waveforms, the packing, the routes, the FASM and the timing path are exactly what bob's tools produced for this design. The placement chapter also runs a small annealer live in your browser, on the design's real nets.

1The source

Twenty lines of Verilog. Everything after this is a tool translating it.

wide.v has a 12-bit counter and an 8-bit LFSR (a shift register whose new bit is an XOR of old ones: a cheap random sequence). BTN0 steps both; BTN1 resets both.

The three LEDs show parities: whether an odd number of bits are 1 in parts of the counter and the LFSR, mixed with the switches, so every register reaches an output. A tool may delete any logic that reaches no output.

2What yosys reads

Synthesis starts by turning each line into generic cells: adders, multiplexers, XORs, flip-flops.

yosys reads the Verilog and builds a netlist of coarse cells, each as wide as its signal: a 12-bit $add for cnt + 1, a $dff per register, a $mux for every if, XORs for ^.

Nothing is tied to bob yet. These cells would suit any FPGA, or a chip.

In bob: software/bob/synth.py runs yosys with bob's own cell library (software/bob/synth/).

3Mapping onto bob's cells

The generic cells become the four kinds of cell bob actually has.

bob's elements offer a LUT (any function of up to 6 inputs), an adder bit on the carry chain, and flip-flops with a clock enable and a synchronous reset or set.

So the 12-bit adder becomes 12 adder bits in a chain. The multiplexers disappear: "if BTN1 reset, else if BTN0 step" is exactly a flip-flop's reset and enable. The XORs are packed into LUTs.

4One LUT, up close

A LUT is a truth table. Here is one of the seven, bit by bit.

A 4-input LUT is 16 bits. The four inputs form an address from 0 to 15; the bit stored at that address is the output. yosys writes the 16 bits as INIT, the last bit first.

This one is the parity of four bits: the output is 1 exactly when an odd number of inputs are 1. That is a ^ b ^ c ^ d, one piece of an LED's parity.

bob's LUTs have 6 inputs (64 bits). A 4-input function fills 64 bits by repeating: the table ignores the unused inputs.

5Proving nothing changed

Before anything goes further, bob checks that the mapped netlist still does what the Verilog says.

software/bob/equiv.py simulates the source Verilog and the mapped netlist side by side in iverilog, with the same random switch and button inputs, for 300 clock cycles.

After every clock it compares every register and every output. If a single bit differs, the build stops right here, naming the cycle and the net: a bug in synthesis never reaches the board.

6Packing

39 loose cells become elements, and elements become CLBs of four.

Packing (VPR's first step) groups cells that belong together. An adder bit and the flip-flop it feeds share one element; four elements share one CLB, whose crossbar lets them reach each other cheaply.

Elements run in one of two modes. dd (Double Duty) uses the adder with its LUT still free for other logic; frac splits the LUT into two smaller ones.

7Placement

Where on the grid should each CLB go? Close to the things it talks to.

The placer wants short wires. For each net it measures the box around the blocks it joins (half-perimeter wirelength); the total is the cost.

Simulated annealing: start anywhere, then keep swapping blocks at random. A swap that lowers the cost is kept. One that raises it is sometimes kept too, while the "temperature" is high, so the search can climb out of a bad corner. The temperature falls, and the placement freezes into a good one.

The anneal on the right runs in your browser, on wide's real nets. The last step is VPR's real result.

VPR also keeps the counter's CLBs stacked in one column, because the carry runs straight up; this small demo leaves that rule out.

8Routing

Every net needs a path of wires and switches from its source to its sinks.

Between the tiles run channels of wires (36 tracks each in bob). The router finds, for every net, a chain of wire segments and switches from the block that drives it to every block that reads it.

VPR's router (PathFinder) routes every net, then looks for wires two nets both want, makes those dearer, and routes again, until no wire is shared. On bob's thin routing that negotiation is what decides whether a big design fits at all.

9FASM: the result as text

Every switch that must be on, as one readable line.

FASM (the FPGA Assembly format of the open-source FPGA tools) writes each configuration setting as tile.feature = value: an element's LUT table, its flags, a crossbar select, a routing multiplexer's choice.

software/bob/fasm_from_vpr.py writes it from VPR's result and checks every line is legal for this device. bitgen.py then puts each value at its bits: volume 3's frames.

10The critical path

How fast can the design run? As fast as its slowest path allows.

software/bob/timing.py follows every path from a flip-flop to the next through the configured routing, adding each hop's delay: measured on the real chip for routing and crossbar hops, estimated for the rest.

The slowest one is the critical path. Here it is the counter's carry, climbing four CLBs up one column: bit 0 has to wait for nothing, bit 11 for all the others.

11The model check

One last proof, on the bits themselves.

software/bob/model.py is bob in software: it reads the configuration word and computes what every LUT, adder, flip-flop and routing multiplexer does. The build runs it on the new bits with the same inputs as step 5 and compares the LEDs with the source.

Only then is the .bit written. The next time it is checked is on the board: the LEDs against the same model.
