bob, bit by bit

bob is an FPGA that we built ourselves, running inside the chip of a PYNQ-Z2 board. This page explains how it works from the ground up. You only need to know a few logic gates and that a memory cell holds a 0 or a 1. Every chapter has a live diagram: press Next to go one step at a time, Play to watch, and click the switches to try things yourself.

1Gates: the smallest decisions

Everything digital is built from gates. A gate looks at its inputs and answers with a 0 or a 1.

An AND gate answers 1 only when both inputs are 1. An OR gate answers 1 when either input is 1. XOR answers 1 when the inputs differ. NAND is AND with the answer flipped.

The table beside the gate is its truth table: every possible input, and the answer for each. With two inputs there are only 4 rows. Keep this table in mind. The whole trick of an FPGA is that it stores truth tables in memory instead of building fixed gates.

Try it: flip A and B, and change the gate. The highlighted row is the one being used right now.

2Remembering a bit

An FPGA has to remember how it is wired. Each choice is one bit, kept in a tiny memory cell.

Connect two inverters in a ring: the output of one feeds the other. If the left one outputs 1, the right one outputs 0, which keeps the left one at 1. The pair holds itself. That is an SRAM cell (6 transistors in silicon). Writing means pushing the ring into the other state.

In an FPGA these bits are called configuration bits. They don't hold your data. They hold the FPGA's own settings: which truth table each LUT has, and which wire goes where. Load different bits and the same chip becomes a different circuit.

In bob: the board runs M21 with 32,896 configuration bits. Most of them are flip-flops in the host chip, and each is written like this cell.

3The multiplexer: a switch you control with bits

A mux (multiplexer) picks one of its inputs and passes it to the output. Some select bits say which one.

A 4-input mux has two select bits, S1 and S0. Together they count 0 to 3, and that number is the input that gets through. A 2-input mux is just gates: out = (A AND NOT S) OR (B AND S). Bigger muxes are trees of small ones.

This matters twice in an FPGA. First, a mux is how a LUT reads its truth table (next chapter). Second, a mux is how a wire chooses where its signal comes from (chapter 8). If the select bits are configuration bits, the mux is a switch that you set once, when you load the design.

Try it: set the four data inputs, then change S1 and S0 and watch which one reaches the output.

4The LUT: a truth table you can rewrite

Put a truth table in SRAM cells, and let the inputs drive a mux that reads it. That is a Look-Up Table.

A 2-input LUT has 4 SRAM cells, one per row of the truth table. The inputs A and B are the mux's select bits, so they pick the row. The output is whatever bit is stored there.

To make an AND gate, store 0 0 0 1. To make an XOR, store 0 1 1 0. The hardware does not change at all: only the stored bits change. This is why one FPGA can become any circuit.

In bob: every LUT has 6 inputs, so it holds 2⁶ = 64 bits and can be any function of 6 inputs. It can also split into two 5-input LUTs that share their inputs ("fracturable", as in AMD's chips).

Try it: load a gate with the buttons (watch the bits go into the cells), then flip A and B.

5Why an FPGA needs flip-flops

LUTs alone can only compute answers from the inputs you give them right now. Anything that counts or remembers needs a flip-flop.

Try to build a counter from logic alone: take the count, add 1, and feed the answer back to the input. The new value immediately comes round again, gets 1 added, and comes round again... The wire never settles. A single inverter fed back to itself does the same thing, flipping as fast as the silicon allows: a ring oscillator.

A D flip-flop fixes this. It copies its input D to its output Q only at the moment the clock rises, and holds Q steady the rest of the time. Put one in the loop and the counter moves exactly one step per clock tick. The flip-flop cuts the loop into steps.

So every logic element in an FPGA pairs a LUT (the "thinking") with a flip-flop (the "remembering"). A configuration bit chooses whether the output comes from the flip-flop or straight from the LUT.

Watch the top panel oscillate, then tick the clock in the bottom panel: Q only changes on the rising edge.

6The logic element

bob's basic building block: a LUT, a carry, and two flip-flops, with configuration bits deciding how they connect.

Each logic element has:

  • a 6-input LUT (64 configuration bits)
  • a carry path, so that neighbouring elements can add numbers quickly (the carry goes element to element without using the routing)
  • two flip-flops, with enable (CE) and reset (SR) inputs
  • small muxes, set by flag bits, that choose "registered or not" for each output

Together that is 106 configuration bits per element in bob (64 truth-table bits, 12 flags, and 30 bits for the crossbar that feeds its inputs, next chapter).

Step through it, and flip ff_en to see the output switch between "straight from the LUT" and "from the flip-flop".

7The CLB: four elements that talk to each other

A CLB (Configurable Logic Block) groups elements so that nearby logic can connect without leaving the block.

A bob CLB has 4 logic elements, 16 inputs from the routing and 8 outputs back to it. In front of the elements sits a crossbar: every one of the 4 × 6 = 24 element inputs has its own mux. Each mux can pick any of the 16 CLB inputs or any of the 8 element outputs (feedback), or a constant 0 or 1.

Why group them? Signals that stay inside a CLB take one short hop through the crossbar instead of a long trip through the routing. Designs pack tighter and run faster. bob chose 4 elements per CLB after measuring 4, 6, 8 and 10: more elements need a bigger crossbar, and every crossbar mux costs chip area.

Try it: click an element input (a column) to change where it gets its signal. Each column is one 26-way mux, set by 5 configuration bits.

8Routing, and why there are so many muxes

CLBs sit in a grid. Between them run wires, and every wire needs a way to choose its signal.

An FPGA doesn't know in advance which CLB will talk to which. So it lays wires (tracks) along every row and column, and at each point where a signal could change direction, or enter or leave a CLB, it puts a mux:

  • a connection box mux picks which track feeds a CLB input
  • a switch box mux picks where a track continues from

Connecting CLB A to CLB B means setting the select bits of every mux along one path. With thousands of possible paths, you need thousands of muxes. This is where most of an FPGA goes: not the logic, the wiring.

In bob: 40 tracks per channel, 3,396 routing muxes plus 1,176 crossbar muxes, for 196 LUTs. VPR (the router) chooses the path; the result is just select values for these muxes.

9All the settings, as one long string of bits

Truth tables, flags and mux selects together form the configuration: one long string of bits, the bitstream.

bob can take the bits in two ways:

  • The scan chain: every configuration bit sits in one giant shift register. You push bits in one at a time; after 32,896 pushes every bit is in place. It's simple, but you have to rewrite everything to change anything.
  • Frames: the bits are cut into frames of 128 bits (4 words of 32). Each frame has an address (FAR). You send "write frame 17" and 4 words, and only frame 17 changes. This is how AMD's real chips do it (their user guide UG470), and it makes partial loads possible.

Every stream ends with a CRC, a checksum. If even one bit arrived wrong, the checksum doesn't match and bob refuses to start.

In bob (M21): 32,896 bits = 257 frames. Readback reads the frames back out, so you can check what went in.

10A full load, step by step

From a blank fabric to a running design: clear, send the frames, check, then wake up in a safe order.

Loading a design (./bob load design.bit) goes like this:

  • JPROGRAM clears every configuration bit: the fabric goes dark.
  • A sync word (AA995566) says "a bitstream starts here", and the IDCODE check makes sure the file was made for this chip.
  • The frames are written, and the frame address counts up by itself.
  • The CRC is compared.
  • Startup runs in a fixed order: release the reset (GSR), then let the pins drive (GTS), then let the flip-flops change (GWE), then light DONE.

The order matters. The flip-flops only start moving after every bit is in place, so the design never runs half-loaded.

11A partial load: change a running design

Rewrite only the frames that differ, while everything else keeps its state.

Say a design has a counter and an AND gate, and you want an OR gate instead. The two designs differ in one truth table, which lives in one frame. A partial load:

  • freezes the design: the clock is held, so no flip-flop changes (the command is AGHIGH)
  • writes only the changed frame (1 of 257)
  • checks the CRC
  • releases the clock (LFRM)

The counter never notices: it had 5 before and still has 5 after. The next tick makes it 6. Only the gate changed.

In bob: ./bob load new.bit --partial. The board test partial-cluster even rewrites one element of a CLB while its neighbours keep counting.

12LUTs that load themselves (M22)

bob's next step: store each truth table in a real LUT of the host chip, filled by shifting bits in.

bob runs inside another FPGA, AMD's XC7Z020. In chapter 4 each bob LUT was 64 flip-flops plus a big 64-to-1 mux, all built from the host chip's own parts. That costs a lot of the chip.

AMD's chips have a special LUT, the CFGLUT5, whose 32-bit truth table can be rewritten while the chip runs, by shifting bits in one per clock. M22 keeps each bob truth table in two of these. The frame buffer feeds the bits in over 32 clocks, while the next frame is still arriving.

The result, measured: a bob CLB drops from 469 host LUTs + 424 flip-flops to 193 LUTs + 48 flip-flops. That space pays for a 9 × 9 grid: 81 CLBs, 324 LUTs.

Press Play to watch a truth table shift into a CFGLUT5, one bit per clock.

13BRAM: a block of real memory

For storing data (not settings), an FPGA has dedicated memory blocks.

You could build memory from LUTs and flip-flops, but it would eat the fabric. So FPGAs include block RAMs: dense memories with their own address and data pins, connected to the routing like a big CLB.

bob's BRAM holds 1024 words of 18 bits and has two ports, A and B, that can work at the same time. It is synchronous: you give an address, and the data appears after the next clock tick.

Its initial contents come from the bitstream too (as frames of their own), so a design can start with a lookup table or a program already in memory.

Step through a write and a read. Notice that the read data appears one clock after the address.

14DSP: a fast multiplier

Multiplying is common (filters, audio, AI) and expensive in LUTs, so it gets its own hardware.

A 25 × 18-bit multiplier built from LUTs would take hundreds of them. A DSP slice is a ready-made multiplier plus an adder: it computes P = A × B + C, or keeps adding into P every clock (multiply-accumulate), which is the heart of a digital filter.

bob's DSP follows AMD's DSP48E1: A is 25 bits, B is 18, P is 48, with optional registers inside. Two DSPs are chained, so one can pass its result straight to the next.

In bob: the fir and fir16 examples are digital filters. They multiply and add every clock.

15The clock, and how fast a design can run

A signal takes time to travel through LUTs and wires. The clock must wait for the slowest path.

Between two flip-flops, a signal passes through LUTs and routing muxes, and each one adds a little delay. The longest such path is the critical path. If the next clock tick arrives before the signal does, the flip-flop captures a wrong, half-finished value.

bob's clock is the board's 125 MHz clock with an enable (gce): the fabric only acts on the ticks where gce is 1. bob's tool timing.py adds up the delays of your design's real path and spaces the gce pulses just far enough apart, with a safety margin.

In bob: ./bob build design.v --hz auto runs a design as fast as its own path allows. On the board the computed clock had a 4.5× margin.

Try it: shorten the clock period with the slider. When it gets shorter than the path, the capture goes wrong.

16From Verilog to LEDs

How a design written as text ends up as configuration bits on the board.

  • yosys turns Verilog into a netlist of LUTs, adders and flip-flops (synthesis)
  • VPR packs them into CLBs, places the CLBs on the grid, and routes the wires
  • FASM lists every configuration setting that the placement and routing chose
  • bitgen turns that list into the bitstream (and checks it survives the round trip)
  • timing computes the critical path and the clock
  • JTAG carries the bits to the board, and the LEDs light

At every step bob checks itself against the source Verilog, a "golden" netlist and a Python model of the fabric, so a mistake is caught where it happens.

17JTAG: four wires to talk to the chip

The bits travel from the laptop, through a small Pico board, over four wires.

JTAG is a standard test port. It has four wires: TCK (the clock), TMS (steers a small state machine), TDI (data in) and TDO (data out). Every TCK tick shifts one bit in on TDI and one bit out on TDO.

First you shift in an instruction (like "I'm sending configuration" or "give me your ID"). Then you shift the data for that instruction. bob uses AMD's instruction codes (JPROGRAM, CFG_IN, JSTART) and adds its own (CAPTURE to read every flip-flop, INTEST to drive the pins).

In bob: a Raspberry Pi Pico runs DirtyJTAG and wiggles these wires for the Mac. TCK runs at 100 kHz, so a full load takes about a third of a second.

AWords used on this page

FPGA

One stored setting of the FPGA: a truth-table entry, a flag, or part of a mux select.

All the configuration bits for one design, in the order the chip takes them.
LUT
Look-Up Table: a small memory holding a truth table, read by a mux driven by the inputs.

A 1-bit memory that updates only on a clock edge; it gives a circuit steps and state.

LUT + carry + flip-flops, bob's basic unit (called a BLE or fle elsewhere).

The wires between blocks, and the muxes (connection and switch boxes) that steer them.

128 configuration bits with one address; the unit of writing and partial loading.
CRC
A checksum over the stream; a mismatch stops the design from starting.
BRAM
Block RAM: a dedicated 1024 × 18 memory block.
DSP
A dedicated multiplier + adder block.
Critical path
The slowest path between two flip-flops; it sets the fastest clock.
