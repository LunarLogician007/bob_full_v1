bob, layer by layer

Volume 1 explained the pieces: gates, memory bits, multiplexers, LUTs, flip-flops. This volume builds the whole FPGA out of them, one layer at a time. One element becomes a cluster, clusters tile a chip, and wires join the tiles. Every switch gets a memory bit, a tool fills those bits in, and a cable pours them into the chip.

Each picture builds up in steps. Press Next (or → on the keyboard) and one new thing appears, with a sentence saying what it is. Every drawing comes from the real chip: the grid, pads and frames from device.json, and the counter example's packing and routes exactly as bob's tools made them.

1One logic element

Start with the smallest thing that computes: a lookup table, a little adder, and two flip-flops.

A lookup table (LUT) with six inputs is 64 memory bits and a 64-to-1 multiplexer. The six inputs form an address, and the bit stored there is the answer. Any function of six inputs is just a different set of 64 bits.

bob's LUT can also split in two. Five inputs address each half, so it can compute two smaller functions at once: O6 and O5.

Adding numbers is so common that the element has a carry chain: a fast wire that passes the carry bit to the element above, as in schoolbook addition.

bob: this is hw/src/clb/ble.sv. Since M24 the adder can take two inputs directly (Double Duty, from an FPL 2025 paper), so the LUT stays free for other work.

2Four elements and a crossbar

Elements come in groups of four. The group shares a set of inputs, and a crossbar lets each element take any of them.

Why group them? Signals pass between neighbours all the time. Inside a group they need no long wires: an element's output goes straight back to its neighbours.

The crossbar is a set of multiplexers, one for each element input. Each can choose any of the group's 16 inputs or 8 outputs, or a constant 0 or 1.

Which input each multiplexer chooses is again stored in memory bits. Configuring an FPGA is mostly setting these choices.

bob keeps these choices in small shift-in lookup tables (CFGLUT5, a primitive of the host chip), so each crossbar multiplexer is five tiny tables and an OR gate.

3The CLB tile and its pins

Wrap the group in a box with pins, and you have the CLB, the brick the whole chip is built from.

From the outside a CLB is just pins: 16 inputs, 8 outputs, a carry in at the bottom and a carry out at the top, plus a shared clock enable (ce) and reset (sr).

Everything outside the CLB, the wiring between tiles, only needs to know where these pins are. That separation lets a tool treat the chip as a grid of identical bricks.

4Tiling the chip

Put the bricks in a grid, add memory and multiplier columns, and ring it with pads.

bob's grid is CLBs. Two columns are special: one holds BRAM blocks (1024 × 18-bit memories), one holds DSP blocks (fast multipliers). Each block is five rows tall, because it is much bigger than a CLB.

Around the edge is a ring of I/O pads: where signals enter and leave. A few are wired to the board's switches, buttons and LEDs.

bob: real FPGAs are built in columns like this too, and so is their configuration memory (chapter 6).

5Wires between the tiles

Channels of wires run between the tiles. Switches where they cross let a signal turn corners.

Between every row and every column runs a channel of wires. Each wire is tiles long, so a signal can cross several tiles without passing a switch.

Where channels meet sits a switch box: a wire arriving there can continue onto one of 3 others. Next to each CLB, a connection box lets each input pin listen to a few of the channel's wires.

Every switch box and connection box is a multiplexer, with memory bits choosing its input. That is why FPGAs are mostly wiring: routing multiplexers take most of bob's host area.

bob: the last two steps draw real routes: the counter example's nets exactly as VPR routed them.

6Every choice is a bit: the configuration memory

Collect every table bit, every multiplexer's choice and every flag, and arrange them in frames.

A multiplexer with 5 inputs needs 3 bits to say which one it passes (and 0 means none). Add them up over the whole chip and you get the configuration: one long string of bits that says what the FPGA does.

The bits are cut into frames of 128, column by column, the way AMD's chips do it (UG470). A frame is the smallest piece you can rewrite, which is what makes partial reconfiguration possible (chapter 10).

7From Verilog to bits: the counter

Follow one real design through bob's tools: synthesis, packing, placement, routing, FASM, bits, packets.

Synthesis (yosys) turns the Verilog into LUTs, adders and flip-flops. Packing groups them into elements and CLBs. Placement chooses a grid spot for every CLB and pad. Routing picks wires for every signal.

The result is written as FASM: one line per setting. bitgen turns the lines into the configuration bits, and those go into UG470-style packets for the cable.


    

    

  






  
8Pouring the bits in

  
A JTAG cable ticks the bits in one at a time. Frames land in memory, tables load themselves, and a startup sequence switches the design on.

  

    

      
JTAG is a 4-wire test port that almost every chip has. On each tick of TCK one bit enters on TDI. 32 bits make a word; words make packets; a packet says "here is frame number n".

      
Most frames land in flip-flops. Frames holding lookup tables and crossbar choices go on to a loader, which shifts them into the CFGLUT5 tables, 32 ticks per frame.

      
Then comes startup: release the global reset (GSR), turn the outputs on (GTS), allow writes (GWE), and light DONE.

    

    

  






  
9Running, and how fast

  
The design ticks on its own clock. How fast it may tick depends on its slowest path.

  

    

      
bob's design clock is a pulse (gce) sent every so many cycles of the board's 125 MHz clock. Between two pulses, every signal must get from one flip-flop, through wires and LUTs, to the next flip-flop.

      
The slowest such path is the critical path. bob adds up its hops and multiplies by a safety margin, the guard band. It refuses to load a design whose clock would be too fast for that. This is the timing contract.

      
bob: the delays are still estimates, so the margin is 2×. The board has shown about 5× of real headroom. Measured delays (the delay_paths.rpt of a build) bring the margin down to 1.25×, which makes every design run faster.

    

    

  






  
10Changing a running design

  
Freeze, rewrite only the frames that change, release. The rest keeps its state.

  

    

      
Because the memory is cut into frames, you can rewrite just a few. bob first freezes the design (AGHIGH: no more clock pulses), writes the changed frames, checks a CRC, and releases it (LFRM).

      
A counter running beside the changed part keeps its value across the rewrite.

    

    

  






  
11Time travel

  
Save every flip-flop of a running design, run on, and put the saved state back, or hand it to the simulator.

  

    

      
To save: freeze, and read every flip-flop through CAPTURE.

      
To restore: every flip-flop has an INIT bit in the configuration, the value it takes on a global reset. bob writes the saved values into those INIT bits, pulses the reset (GRESTORE, a UG470 command), and writes the original INIT bits back. Every flip-flop jumps to its saved value at once.

      
The saved state can also go into bob's software model, run there, and come back onto the chip.

      
bob: bob snap save a, bob snap restore a, bob snap sim a --steps 10. New in M25.

    

    

  






  
12Where bob actually lives

  
bob is itself a design, running inside a real AMD chip: an FPGA made of another FPGA's parts.

  

    

      
The PYNQ-Z2 board carries an AMD Zynq XC7Z020: two ARM cores and a block of programmable logic. Vivado builds bob into that logic once. From then on, bob's own tools configure bob over the Pico's JTAG cable, and a new design never needs Vivado.

      
Every part of bob is made of the host's parts: its lookup tables are the host's shift-in tables, its routing multiplexers are the host's LUTs and wide multiplexers, its configuration bits are the host's flip-flops.
