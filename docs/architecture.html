Section 1

What it had to do

The architecture is not arbitrary. Each structure below exists because of a requirement, and several of the stranger details — five select bits for twenty sources, a reset that is deliberately synchronous, a clock that comes from the debug probe — are direct consequences.

3 primitives Section 2

Everything is one of three things

The whole fabric reduces to three primitives. Nearly all of it is the first one: a 2:1 multiplexer, repeated eleven thousand times.

The primitives, at gate level
A 2:1 multiplexer is two AND gates, an inverter and an OR: o = (a · s̄) + (b · s). On a real FPGA this costs a fraction of one LUT, which is why building a soft FPGA inside a hard one is affordable at all — the hard fabric's 6-input tables absorb several of these each.

64 bits · 63 muxes Section 3

The lookup table

A LUT6 holds 64 configuration bits and answers one question: for this combination of six inputs, what is the output? Bit n is the answer for input vector n. There is no logic in it — only memory and a tree of multiplexers.

Why a mux tree and not an array index

Written as o = INIT[i] it would still synthesise to a tree, but the structure would be the tool's choice rather than the architecture's. Writing the five levels explicitly fixes where the fracture tap sits: after five levels the survivor is already a complete 5-input function of i[4:0] over INIT[31:0]. That wire is o5 — a second, smaller lookup table hiding inside the first, for free.

71 bits Section 4

The logic block

A lookup table alone cannot add or remember. Two structures fix that, and seven configuration bits above the truth table decide which paths are live.

The carry chain

Ripple carry through general logic is slow, because each bit's carry has to traverse a whole LUT. The fix, on every commercial FPGA and here, is a dedicated path: the LUT computes only the propagate term and two hard gates do the rest. The sum is prop ⊕ cin (an XOR), and the carry out is cin when propagate is true, otherwise a generate term (a 2:1 mux). One block becomes one bit of an adder, and the carry crosses a tile in one gate rather than one lookup.

The flip-flop

Synchronous reset, clock-enable independent — FDRE/FDSE behaviour. Holding sr keeps the flop reset, which is idempotent and so safe to hold across a scan that takes thousands of clocks.

110 bits · 682 muxes Section 5

The routing

A logic block alone is not an FPGA. What turns sixteen of them into one is the routing, and a tile has two kinds. A connection box decides what the block sees; a switch box decides what the tile passes on. Both are the same circuit with a different multiplexer count, so both are instances of one module.

Why twenty sources, and why five bits

Every multiplexer in a tile chooses from the same twenty-entry bus: two constants, the block's own two outputs, and four tracks from each of four edges. Twenty needs five select bits; five bits address thirty-two, so twelve encodings are unreachable. Rather than leave them undefined, the hardware pads the source bus to thirty-two entries with hard zeros, so a malformed bitstream reads a defined 0 instead of an X. That padding is also why the gate cost below is a 32:1 tree rather than a 20:1 one.

A 20:1 source mux, built from the primitive
Five levels, 16 + 8 + 4 + 2 + 1 = 31 multiplexers per source mux. A tile has 6 of them in the connection box and 16 in the switch box: 22 × 31 = 682.

181 bits Section 6

Every bit, individually

The complete tile word. Bit 0 is the low end of the scan chain, so it is the first bit to leave TDI. In the fabric, tile n occupies bits 181n through 181n + 180, with tile (0,0) first.

Select fields are little-end first: sel[0] is the weight-1 bit. So the connection box field for i0 occupies bits 71–75 with bit 71 as the least significant, and the switch box field for output N0 occupies 101–105. Offsets are 71 + 5k for LUT input k, and 101 + 5(4d + t) for direction d ∈ N,E,S,W and track t.

Section 7

What it costs

Counting in 2:1 multiplexers, the unit everything is built from. The routing dominates the logic by nearly eleven to one — which is not a flaw in this design but the standard result for FPGA fabrics, and the reason routing architecture is where commercial effort goes.

Configuration storage is counted twice over because the chain needs both a shift register and a holding register: the fabric must not see partial configuration while 2896 bits ripple past. That separation is also what makes the chain readable — the holding register is re-captured at Capture-DR, so a scan can read back what is actually loaded.

2896 bits Section 8

Sixteen tiles, and one rule

Tracks are point to point between neighbours and the track number survives the hop. Driving a tile's switch box output in direction D on track t makes that signal arrive at the neighbour in direction D, on the opposite side, on the same track.

That is the whole routing model, and the router is a direct transcription: a breadth-first search over tiles, one switch box multiplexer per hop. A multiplexer already carrying the same signal is free to cross again, which is the entirety of fanout support.

Where the pads meet the fabric

Signals flow west to east. pad_i[3:0] arrive on every row's west edge on tracks 0–3; pad_i[5:4] on every column's south edge on tracks 0–1; pad_o[k] is row k's east edge, track 0. Column 0 therefore reaches four inputs directly and row 0 all six — anything further in has to be routed there, which is what makes this a fabric rather than a lookup table with extra steps.
