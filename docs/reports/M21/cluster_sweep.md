# M21 cluster sweep: N, the crossbar and the grid, measured

`software/bob/sweep.py` (tables below regenerated by `software/bob/sweep.py --report` from
`build/sweep/`). Plan: M21 goal 2, *size it by measurement first*. The decision it feeds
(N, crossbar, grid) is the user's, before any Vivado build.

## Method

For every configuration of the cluster knobs in `software/bob/device.py`
(`ARCH["cluster"]`: N elements per CLB, I CLB inputs, crossbar `full` or `half`,
fracturable LUTs on) and for M16's one-LUT CLB (the committed M20 architecture) as the
baseline:

1. **Channel width.** VPR (OpenFPGA's image, the flow's own) routes every example with a
   binary search on W. The architecture is then built at 1.3 × the widest example's
   minimum (VPR's low-stress margin), rounded to even.
2. **Configuration bits.** The rr graph VPR writes at that W becomes a `Device`: the bits
   per CLB tile and per LUT are exact, not estimated.
3. **Routing and timing.** Every example is routed again on that graph. The critical
   path is VPR's, with **bob's own delays** substituted into the architecture
   (`software/bob/delays.json`: routing mux 3.61 ns, connection box 2.06 ns, LUT 3.4 ns,
   carry 1.0 ns; the crossbar is timed as a routing mux until M21's build measures it).
4. **Host area.** The generated fabric (`bob_fabric` with the cluster, configuration
   bits as inputs so nothing folds) through yosys `synth_xilinx`. The M16 fabric through
   the same flow is 22,584 LUTs; Vivado built the whole M16 design, which yosys puts at
   32.8k, in 20,498. That ratio (about 0.62) turns yosys numbers into expected Vivado ones.

The examples are the eleven committed ones plus **fir16**, the new M21 example (a 16-tap
FIR in logic: 147 LUTs, 10 adders, 58 flip-flops; round 1 ran an earlier, larger version
with 4-bit samples: 213 LUTs).

## Findings

1. **A half (depopulated) crossbar costs more than it saves.** With half the sources on
   each element input, CLB inputs are no longer equivalent, so the router must reach one
   particular pin; VPR needs W = 66–112 against 46–56 for the full crossbar, and the wider
   channels cost more configuration bits than the smaller crossbar muxes save (153–159
   bits per LUT against 142–152). Every round-2 configuration is full.

2. **Configuration bits per LUT hardly move with N** (141–159 across every cluster,
   149 for M16's CLB), as the plan predicted: the crossbar grows as N², but the routing
   is paid once per tile.

3. **Host LUTs per guest LUT grow with N.** This is the number that decides the grid on
   this chip, and it runs the other way from silicon. Every multiplexer of the guest
   fabric is host LUTs; a crossbar multiplexer of an N=10 CLB selects from 62 values and
   is 35 yosys LUTs, and the CLB has 60 of them (about 2,100 LUTs a CLB, against 500 for
   its ten elements). At about 200 LUTs: **N=4 289, N=6 337, N=8 372, N=10 421** host
   LUTs per guest LUT (yosys), against 226 for M16's CLB. Betz's input count
   (I = K(N+1)/2) saves about 5%.

4. **The clock effect is large.** Logic inside a CLB reaches its neighbours through the
   crossbar, and a carry chain runs through the elements with no routing at all.
   `software/bob/timing.py` on the committed VPR results, M20 against the N=10 fabric:

   | design | M20 critical path | M21 (N=10) | faster |
   |---|---|---|---|
   | counter | 25.4 ns, 9 routing hops | 13.5 ns, 0 hops | 1.9× |
   | blinky | 28.4 ns, 12 hops | 15.5 ns, 0 hops | 1.8× |
   | wide | 55.9 ns, 22 hops | 19.5 ns, 1 hop | 2.9× |
   | big | 64.5 ns, 28 hops | 23.5 ns, 1 hop | 2.7× |
   | atspeed | 120.2 ns, 39 hops | 55.5 ns, 6 hops | 2.2× |
   | fir | 57.1 ns, 16 hops | 50.5 ns, 10 hops | 1.1× |
   | fir16 | does not fit | 130.1 ns, 26 hops | |

   Smaller N keeps most of it (round 2, VPR with bob's delays: `big` 54 ns at N=4, 44 at
   N=10, 65 on M16's fabric).

5. **Wirelength drops by 3–8×** for the same designs (`big` 1499 → 169–393, `atspeed`
   1011 → 162–263), which is what relieves the routing congestion M16 ran into.

6. **What fits.** The budget for the fabric is about 50k yosys LUTs (the whole design
   near 55k, about 34k in Vivado: 64% of the XC7Z020, against M16's 38.5%). A 360-LUT
   cluster fabric (round 1) is 103k–147k: it does not fit at any N. fir16 needs 153
   elements, packed into 45 CLBs at N=4 and 15 at N=10.

## Recommendation (for the user's approval)

See the hand-off note in `HANDOFF.md` §1: the decision is N (with it the crossbar and I)
and the grid. The code has N, I, the crossbar and the grid as knobs of `device.py`; a
change is `make rrgraph`, `make device`, `make vpr` and the pinned sizes in
`tests/test_device.py`.
