# M2 hardware test: scan-chain configuration plane on `cfg_test_top`

Build: `hw/build.cfg` has `tag = M2`, `top = cfg_test_top`, `idcode = 4BEEF093`, `usercode = 00000002`. Replace `E:\bob_full_v1\hw`, run `build.tcl`, program, and copy `bob_vivado\out\M2\` to `docs/reports/M2/`.

This top is **not** the fabric. It holds only the new TAP and the config plane (64-bit chain, 4 tiles × 16). The fabric self-test comes back at M3, so the regression here is `idcode` + `bypass`. The 4×4 fabric designs can't run on this bitstream.

LEDs on this top: **LD2..LD0 = chain bits 2..0 after startup (GTS released), LD3 = DONE.**

## Automatic (`make hwtest M=M2`)

| check | pass means |
|---|---|
| idcode | `0x4BEEF093` through the 6-bit TAP (Test-Logic-Reset selects IDCODE) |
| bypass | 1 bit, with a 6-bit BYPASS instruction |
| usercode | `0x00000002` |
| ir-capture | after JPROGRAM: LSBs `01`, INIT_B = 1, DONE = 0, COMMITTED = 0 |
| chain-length | a marker through CFG_OUT comes out after exactly 64 bits |
| load-readback | 4 random chains: commit with CRC, CFG_OUT twice equals the chain |
| crc-reject | one flipped bit: CRC_ERR, previous chain still read back |
| len-reject | 63-bit scan: LEN_ERR, previous chain kept |
| startup | JSTART without commit: DONE stays 0; with commit: GSR, GTS, GWE, DONE in order |
| capture | counter advances between two CAPTUREs; SW/BTN fields reported |
| jprogram | counter held at 0 by GSR, chain reads back 0, DONE 0 |

## By hand (`--manual`)

Run these on the Mac from `software/host/` while watching the board:

- [ ] `./cfgplane.py load 0x5`: LD3 (DONE) lights, LD2..LD0 show on-off-on
- [ ] `./cfgplane.py load 0x2`: LD1 only (plus LD3); no JPROGRAM flicker left over
- [ ] `./cfgplane.py capture` with SW1 up and BTN0 held: SW1..0 = 10, BTN3..0 = 0001
- [ ] `./cfgplane.py jprogram`: all LEDs go dark
