# M19 hardware test: the studio app, board pins in block designs, the waveform viewer

**No Vivado rebuild.** Software only; the PL keeps the **M16** bitstream (IDCODE
`0xFBEEF093`). Run it after M18's test, or together with it: `make hwtest M=M19` runs the
whole M18 list first.

## What changed

- **bob studio is a desktop app:** `./bob studio` (add `--probe usb` for the Pico, or
  `--probe fake`) opens its own window, a native macOS window through pywebview, not a browser
  tab. The New Project / Add files dialogs get a **Choose…** button that opens the system's
  file dialog, and **export .vcd** saves through a system Save dialog. `./bob studio --browser`
  (or `software/host/studio.py`) is the old browser tab. Without pywebview installed, `./bob studio`
  says so and opens the browser.
- **All software lives in `software/`:** the studio page moved from `docs/studio/` to
  `software/studio/` (built page `software/studio/studio.html`).
- **Zoom:**
  - The block-design canvas and the Device view have **− / % / + / fit**. Ctrl/⌘ + wheel
    (or a trackpad pinch) zooms about the pointer, a plain wheel scrolls, and dragging the
    empty background pans.
  - The waveform zooms its time axis the same way.
- **Board pins in block designs:** the board blocks start empty, as in Vivado, and hold only
  what you add. **+ input pin / + output pin** offers whole buses (`sw[1:0]`, `btn[3:0]`,
  `led[2:0]`), the board's own pins **SW0 SW1 BTN0–BTN3** and **LD0–LD2**, and scan-only pads.
  A port a wire already uses is always shown. Wiring is a drag from one port (its dot or its
  name) to another, in either direction. A wire to `board.LD1`
  is the same as `board.led[1]`, and driving LD1 both ways is caught as a double drive. Click
  a board block to list its added pins and remove them.
- **Waveform (pad ILA)**, under Program and Debug. It is a logic analyser on the pads that
  needs no extra logic in the design: every scan of the boundary register is one sample of
  all 44 pads.
  - **step:** INTEST with autostep, one sample per user clock, cycle-exact. The inputs are
    held, random, or the real switches. Use a design built with `clock jtag`.
  - **live:** SAMPLE while the design runs on its own clock and your switches, stamped in
    real time.
  - **Trigger:** a signal rises, falls, is 1, is 0 or changes, with a pre-trigger share,
    as in an ILA.
  - Signals carry the programmed design's port names (from its `.pcf`, or the sw/btn/led
    convention). **export .vcd** opens the capture in GTKWave.

## Automatic (`make hwtest M=M19`), about 16 minutes

M18's full list, then:

| check | pass means |
|---|---|
| wave-step | `counter.v` is stepped through INTEST by `padwave.capture` with its own source trace's inputs: 120 captured clocks of LD2..0 equal the source Verilog's (the LEDs must take at least 3 values), and the VCD is written |
| wave-live | **interactive, 8 s.** `switches.v` on the free-running clock. Press Enter, then flip **SW0** and **SW1** several times: every live sample must have LD0 = SW0 xor SW1, and at least 3 of the 4 switch settings must be seen |

## By hand (`--manual`), about 10 minutes

- [ ] `./bob studio --probe usb` opens a **window** titled "bob studio" (not a browser tab). The top bar shows `Pico 0xFBEEF093` with a green dot
- [ ] Zoom: open **Device view**, press **+** twice (the % goes up and the grid grows), drag the empty background to pan, then **fit**. Ctrl/⌘ + wheel zooms about the pointer. In **Block Design** (open `work/examples/bd_demo`) do the same
- [ ] Wiring: New Project → Create Block Design → IP **and**. The board blocks are empty. **+ input pin → SW0**, **+ output pin → LD0**, then drag from **SW0** to **and_0 → a**, from **and_0 → y** to **LD0**, and from **and_0 → b** back to the input block after adding **SW1**. Three wires appear in the canvas and in the wire table
- [ ] Board pins: in `bd_demo`'s block design click **+ output pin**. The dialog lists `led[2:0]` (greyed: already there), **LD0 LD1 LD2** and the free pads. Pick **LD2**: a port `LD2` appears on **board outputs**. Click the board outputs block, then **remove** next to LD2: it goes away. Close without saving (or Save and put it back: the example must stay as shipped)
- [ ] Waveform, step: build and program `work/examples/counter/counter.v` (Sources → Examples → counter, **Generate Bitstream**, **Program Device**). Open **Waveform**, mode **step**, turn **BTN0** on in "hold these", trigger **LD1 rises**, **Run capture**. LD0 toggles every 8 clocks and LD1 every 16, and the red **T** line sits on LD1's first rise. Press **+** and **fit**; click to move the cursor, and the readout under the plot lists every signal's value at it
- [ ] Waveform, live: build `work/examples/switches/switches.v` with **clock run** (right panel: clock `run`, div `15`), program it, choose mode **live**, depth 400, **Run capture**, and flip SW0 and SW1 during the capture (about 2 s). The LD0 trace is SW0 xor SW1 throughout
- [ ] **export .vcd** opens a Save dialog; the file opens in GTKWave (or any text editor: `$var wire 1 ! led_0 $end` ...)
