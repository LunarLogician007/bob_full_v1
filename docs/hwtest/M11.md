# M11 hardware test: real designs live on the board

No RTL change and **no Vivado rebuild**. The M7 bitstream stays in the PL:
- top `bob_top`
- IDCODE `0xABEEF093`
- 4216-bit chain

`hw/build.cfg` stays tagged M7.

Up to M10, every design was clocked one step at a time over JTAG, with its inputs injected through INTEST. M11 runs the designs **the way a user would**:
- on the free-running user clock (`bob build --clock run`)
- on the real switches and buttons

They are still verified: by CAPTURE (registers), SAMPLE (pins and LEDs, read without disturbing anything), CFG_OUT readback of the chain while running, and BRAM readback after stopping.

## New examples

| design | what it does on the board | resources |
|---|---|---|
| `examples/switches.v` | LD0 = SW0 xor SW1; LD1 = BTN0 or (BTN1 and SW0); LD2 toggles on every BTN3 press (synchroniser, edge detector, toggle) | 6 CLBs, 3 registers |
| `examples/fir.v` | 2-tap FIR: x = SW1..0 into a delay line, y = x[n]·h0 + x[n−1]·h1, h0 = {BTN3, BTN2, 1}, h1 = {BTN2, BTN3, 1}; LD2..0 = y[4:2] | 12 CLBs, both DSP slices, 7 registers |

Both are equivalent to their source (iverilog), routed by VPR, and pass the golden co-simulation (`sim/run_cosim_sim.sh`, now 9 designs). The per-design report (cells, CLBs, wirelength, FASM features, chain CRC) is `docs/reports/M11/designs.md` (`tools/bob/report.py`).

## Automatic (`make hwtest M=M11`)

Run it in a terminal: the live checks stop and wait for you. The regression runs first: `idcode`, `bypass`, `selftest`, `chain-length` (4216).

| check | you do | pass means |
|---|---|---|
| bob-switches, bob-fir | nothing | the M10 golden check on the new examples: `bob build` → `bob load`, readback == FASM, 64 clocks with LEDs == source and CAPTURE == golden registers |
| ram-readback | nothing | `bob load` writes **all 1024 words** of the BRAM, then 64 clocks of `ram.v` run through INTEST (BTN0 writes). **JPROGRAM** stops the design (GWE = 0, when USER4 READ is allowed); bram0[0..15] read back == the memory `model.py` computed; chain readback == `.bit` |
| blinky-rate | nothing | blinky with `--clock run --div 15`: its 8 registers read by CAPTURE every 0.5 s for 4 s count at 125 MHz / 2^23 = 14.9 Hz ± 10 % |
| live-blinky | nothing (watch LD0 blink about every 2 s) | 16 counter states seen, each with LEDs == model |
| live-fir, live-mult, live-switches | follow the guide (below) | every burst CAPTURE → SAMPLE → CAPTURE in which the registers didn't move gives LEDs == `model.py`(those registers, those pins); every goal is reached within 90 s; CFG_OUT readback while running == `.bit` |

### What a live check looks like

For `live-fir`, `live-mult` and `live-switches`, hwtest does three things:
1. **Prints a guide:** what the design does; a few input settings with the LEDs they must give (computed from the model, inputs held a few clocks); and a list of goals.
2. **Waits for Enter.** Take your time to read it.
3. **Shows a status line** that updates as you play:

```
           SW1..0=11 BTN3..0=0100  LEDs 110  model 110 ok       goals 5/8   23 s
```

- `LEDs` is what the board shows. `model` is what it must show for those registers and pins. `ok` means they agree.
- A goal ticks off when the board shows it **and** the LEDs agree with the model at that moment. The check ends as soon as every goal is ticked, and prints the goal list with `[x]`.
- It fails at the first `MISMATCH`, or if goals are still missing after 90 s (it lists them).
- Hold each setting for about half a second: the user clock is 14.9 Hz, and fir/mult need one or two clocks to show a change.

The goals, and what the LEDs should be:

**live-switches:**
- LD0 = SW0 xor SW1. LD1 = BTN0, or BTN1 while SW0 is up. LD2 flips once per BTN3 press.
- Goals: SW1..0 = 00, 01, 10, 11; BTN0 (LD1 on); BTN1 with SW0 up and BTN0 released (LD1 on); BTN3 press turns LD2 on; another BTN3 press turns it off.

**live-fir:**
- y = x[n]·h0 + x[n−1]·h1, x = SW1..0, h0 = {BTN3, BTN2, 1}, h1 = {BTN2, BTN3, 1}, LD2..0 = y[4:2].
- Examples (held):

  | inputs | LD2..0 |
  |---|---|
  | SW 11, no buttons | 001 |
  | SW 01, no buttons | 000 |
  | SW 11 + BTN2 + BTN3 | 010 |
  | SW 10 + BTN3 | 100 |
  | SW 11 + BTN2 | 110 |

- Goals: all four switch settings; BTN2 held; BTN3 held; both held; 3 different LED values.

**live-mult:**
- a = {BTN1, BTN0, SW1, SW0}, b = {BTN3, BTN2, SW1, SW0}, p = a·b, LD2..0 = p[7:5]. It only lights for big products.
- Examples:

  | inputs | LD2..0 |
  |---|---|
  | SW 11, no buttons | 000 |
  | SW 11 + all buttons | 111 |
  | SW 11 + BTN0 + BTN1 + BTN3 | 101 |
  | SW 11 + BTN1 + BTN2 | 010 |

- Goals: all four switch settings; each button pressed; 3 different LED values.

**Rerun only one check:** `make hwtest M=M11 ONLY=live-fir` (or `ONLY=live-fir,live-mult`); `idcode` still runs first.

**Without a terminal** (piped, scripted), the live checks run 8 s without waiting and don't require the goals. The result then says "goals not checked".

`live-switches` runs last and leaves `switches.v` running for the manual steps.

### Found by the first M11 run (fixed)

`ram-readback` failed.
- bram0[0..3] matched the model, but bram0[4..7] and bram1 held words from earlier tests (bram1 = 3, 6, 4, 5 from M7's `pipeline-live`).
- The cause: BRAM contents survive JPROGRAM and a new chain, and `bob load` wrote only up to the last non-zero word. A design whose source says those words are 0 therefore ran on stale words.
- The fix: `bob load` writes all 1024 words of every BRAM the design uses, and the `.bit` has a section for each such BRAM even if all its words are zero. UG470 bitstreams likewise initialise every BRAM word. The write uses one IR scan and 1024 DR scans (`cfgplane.bram_fill`).

The checks' logic was run first against a stand-in board (`tests/test_hwtest_fake.py`: `model.py` behind the JTAG instructions, the free-running clock in real time, a simulated person on the switches). They pass. They fail on wrong LEDs, a clock 1.5× too fast, wrong BRAM contents, or nobody touching the switches.

## By hand (`--manual`)

`switches.v` is still running after the automatic checks.

- [ ] switches: LD0 is on exactly when one of SW0/SW1 is up; LD1 follows BTN0, and BTN1 only while SW0 is up
- [ ] switches: each press of BTN3 toggles LD2 once (hold it, nothing more happens; release and press again, it toggles back)
- [ ] fir: `./bob load build/bit/fir_run.bit`, then with no buttons held: SW1+SW0 up → LD0; SW0 up only → all off; SW1+SW0 up with BTN2+BTN3 held → LD1; SW1 up with BTN3 held → LD2
- [ ] ram live: `./bob build examples/ram.v --clock run --div 15 -o build/bit/ram_run.bit` then `./bob load build/bit/ram_run.bit`. The switches pick the address and the LEDs show the word: 00 → LD0, 01 → LD1, 10 → LD2, 11 → all three. Hold BTN2 and press BTN0 at address 00: LD1 lights (the word {BTN3, BTN2, SW1} = 010 was written), and it stays after you release both buttons
- [ ] blinky: `./bob load build/bit/blinky_run.bit`: LD0 toggles about every 2.1 s (q[5] at 14.9 Hz), and LD2..0 count up in binary
