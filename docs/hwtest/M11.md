# M11 hardware test: real designs live on the board

No RTL change and **no Vivado rebuild**. The M7 bitstream stays in the PL:
- top `bob_top`
- IDCODE `0xABEEF093`
- 4216-bit chain

`hw/build.cfg` stays tagged M7.

Up to M10, every design was clocked one step at a time over JTAG, with its inputs injected through INTEST. M11 runs the designs **the way a user would**:
- on the free-running user clock (`bob build --clock run`)
- on the real switches and buttons

They are still verified: by CAPTURE (registers), SAMPLE (pins and LEDs, read without disturbing anything), CFG_OUT readback of the chain while running, and BRAM readback after stopping.

## New examples

| design | what it does on the board | resources |
|---|---|---|
| `examples/switches.v` | LD0 = SW0 xor SW1; LD1 = BTN0 or (BTN1 and SW0); LD2 toggles on every BTN3 press (synchroniser, edge detector, toggle) | 6 CLBs, 3 registers |
| `examples/fir.v` | 2-tap FIR: x = SW1..0 into a delay line, y = x[n]·h0 + x[n−1]·h1, h0 = {BTN3, BTN2, 1}, h1 = {BTN2, BTN3, 1}; LD2..0 = y[4:2] | 12 CLBs, both DSP slices, 7 registers |

Both are equivalent to their source (iverilog), routed by VPR, and pass the golden co-simulation (`sim/run_cosim_sim.sh`, now 9 designs). The per-design report (cells, CLBs, wirelength, FASM features, chain CRC) is `docs/reports/M11/designs.md` (`tools/bob/report.py`).

## Automatic (`make hwtest M=M11`)

The regression runs first: `idcode`, `bypass`, `selftest`, `chain-length` (4216).

| check | pass means |
|---|---|
| bob-switches, bob-fir | the M10 golden check on the new examples: `bob build` → `bob load`, readback == FASM, 64 clocks with LEDs == source and CAPTURE == golden registers |
| ram-readback | 64 clocks of `ram.v` through INTEST (BTN0 writes), then **JPROGRAM** (GWE = 0, where USER4 READ is allowed). bram0[0..7] read back == the memory `model.py` computed for the same clocks; chain readback == `.bit` |
| blinky-rate | blinky with `--clock run --div 15`: its 8 registers read by CAPTURE every 0.5 s for 4 s count at 125 MHz / 2^23 = 14.9 Hz ± 10 % |
| live-blinky, live-fir, live-mult, live-switches | the design runs live on the real switches for 8 s at 14.9 Hz, and the check repeats a burst of CAPTURE → SAMPLE → CAPTURE. When the registers didn't move within a burst, `model.py` given those registers and the sampled pins must produce the sampled LEDs. Afterwards, CFG_OUT readback while running == `.bit`. The result line reports how many input vectors and register states were seen |

**During each `live-*` check, flip the switches and press the buttons** (hwtest prints when each one starts). A check passes with the switches still, but then it only proves one input vector. The count of input vectors in the result shows how much you exercised it.

`live-switches` runs last and leaves `switches.v` running for the manual steps.

The checks' logic was run first against a stand-in board (`tests/test_hwtest_fake.py`: `model.py` behind the JTAG instructions, the free-running clock in real time, a simulated person flipping switches). They pass, and they fail on wrong LEDs, a clock 1.5× too fast, or wrong BRAM contents.

## By hand (`--manual`)

`switches.v` is still running after the automatic checks.

- [ ] switches: LD0 is on exactly when one of SW0/SW1 is up; LD1 follows BTN0, and BTN1 only while SW0 is up
- [ ] switches: each press of BTN3 toggles LD2 once (hold it, nothing more happens; release and press again, it toggles back)
- [ ] fir: `./bob load build/bit/fir_run.bit`, then with no buttons held: SW1+SW0 up → LD0; SW0 up only → all off; SW1+SW0 up with BTN2+BTN3 held → LD1; SW1 up with BTN3 held → LD2
- [ ] ram live: `./bob build examples/ram.v --clock run --div 15 -o build/bit/ram_run.bit` then `./bob load build/bit/ram_run.bit`. The switches pick the address and the LEDs show the word: 00 → LD0, 01 → LD1, 10 → LD2, 11 → all three. Hold BTN2 and press BTN0 at address 00: LD1 lights (the word {BTN3, BTN2, SW1} = 010 was written), and it stays after you release both buttons
- [ ] blinky: `./bob load build/bit/blinky_run.bit`: LD0 toggles about every 2.1 s (q[5] at 14.9 Hz), and LD2..0 count up in binary
