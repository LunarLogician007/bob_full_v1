# M18 hardware test: projects and block designs in bob studio

**No Vivado rebuild.** M18 is software only; the PL keeps the **M16** bitstream (IDCODE
`0xFBEEF093`, 100 CLBs, 145 frames). `hw/` is untouched and `hw/build.cfg` still says
`tag = M16`, so the runner prints `note: hw/build.cfg is tagged M16, testing M18`. That is expected.

## What changed

bob studio now works on **projects** as Vivado does:

- **New Project** makes a folder anywhere on disk: `<name>.bobproj` (the project file),
  `src/`, `bd/`, `ip/`, `constrs/`, `build/`. **Open Project** (or the recent list) reopens it.
- The Project Manager adds or copies `.v` files, sets the **top** (right-click → Set as top),
  and adds `.pcf` files, one of which is active.
- A **block design** canvas holds the project's own modules, 14 IP cores
  (`software/bob/ip/`) and the board's pins (sw, btn, led, scan-only pads). Validate
  checks it; **Generate wrapper** writes `bd/<name>_wrapper.v` (and `constrs/<name>.pcf`
  when a pad is used) and makes it the top.
- Generate Bitstream builds the open project into `<project>/build/<name>.bit`. The command
  line does the same: `./bob build --project x.bobproj`, and `tests/test_project.py` holds the
  two to a byte-identical `.bit`.

The board example is `work/examples/bd_demo/`. It is a project made with these tools:
four IP cores (`counter`, `mux2`, `edge_detect`, `toggle`) wired in the block design
`bd/bd_demo_bd.bd`:

| | |
|---|---|
| LD1..0, SW0 down | a 2-bit counter that counts while **SW1** is up; **BTN0** clears it |
| LD1..0, SW0 up | BTN2..1 (BTN1 → LD0, BTN2 → LD1) |
| LD2 | toggles once per **BTN3** press (a synchroniser, an edge detector and a toggle flip-flop) |

## Automatic (`make hwtest M=M18`), about 15 minutes

All of M16's checks, unchanged: the regression (idcode `0xFBEEF093`, bypass, selftest,
chain-length 18560, the frame checks, the guest designs, partial reconfiguration, BRAM frames,
`bob-big` / `pnr-big`). Then:

| check | pass means |
|---|---|
| bob-bd_demo | `bd_demo` built **from its `.bobproj`** through VPR (the committed route in `software/bob/vpr/bd_demo_bd_wrapper/`). Loaded, it gives LEDs equal to the source's on every user clock, CAPTURE equals the golden netlist's 5 registers, and the CFG_OUT readback equals the `.bit`'s FASM |
| pnr-bd_demo | the same, through bob's own place and route |
| live-bd_demo | **interactive, up to 90 s.** `bd_demo` runs on the free-running clock (about 7.5 Hz) and you work through the goals below. Every stable sample must equal `model.py` |

When `live-bd_demo` starts it prints what the LEDs should show for a few input settings,
then waits for Enter. After Enter, do these in any order. Each is ticked off as the board
shows it:

1. **SW1 up, SW0 down**, all buttons released: LD1..0 count 0, 1, 2, 3 at about 7 steps a second (goal: 3 values seen).
2. Still with SW0 down, **hold BTN0**: LD1 and LD0 go off and stay off.
3. **SW0 up**, press **BTN1** alone: LD0 lights.
4. SW0 up, press **BTN2** alone: LD1 lights.
5. **Press and release BTN3**: LD2 turns on.
6. Press and release BTN3 again: LD2 turns off.

The status line shows your inputs, the LEDs and the model's LEDs, with `ok` or `MISMATCH`.
A mismatch stops the check. The goals are generous: SW positions do not matter for LD2.

`pipeline-live` still runs last and leaves the pipeline on the switches.

## By hand (`--manual`), about 10 minutes

- [ ] Studio on the real board: `python3 software/host/studio.py --probe usb` opens the browser. The top bar shows `Pico 0xFBEEF093` with a green dot
- [ ] File flow: click **Open Project…**, pick `work/examples/bd_demo/bd_demo.bobproj` (it may be under Recent). The Project Manager lists 5 sources with `bd_demo_bd_wrapper.v` in bold (the top), no constraints, and one block design
- [ ] Block design: click `bd_demo_bd.bd`. The canvas shows board inputs on the left, four blocks (cnt, mux, press, tog) and board outputs on the right, with 9 wires. Click **Validate**: the pill says `valid`
- [ ] **Generate Bitstream**: all six stages go green (Synthesis, Place & Route, FASM, Bits, Model check, .bit), and the Project Manager's Outputs shows `bd_demo.bit`
- [ ] **Program Device**: the log says it loaded. Then **Readback and Verify** says it matches. The design runs on the stepped JTAG clock, so the counter moves only when the studio scans. Flip SW0 up and press BTN1: after **Board → refresh** the LEDs view shows LD0 lit
- [ ] New Project from scratch: **New Project…**, name `m18try`, location your home folder, skip sources and constraints, Finish. **Create Block Design…** named `m18try_bd`. From the IP catalog click **not**. Drag from `board inputs → sw` to `not_0 → a`: the log says it wired `board.sw[0] → not_0.a`. Drag from `not_0 → y` to `board outputs → led` (wired as `board.led[0]`). **Generate wrapper**. In the right-hand panel set **pnr** to `python` (a new design has no committed VPR route, and VPR needs Docker: `colima start`). Then **Generate Bitstream**, then **Program Device**: with SW0 down LD0 is lit, with SW0 up it is off (refresh the Board view after each change)
- [ ] Close the studio (Ctrl-C), start it again, and **Open Project…** → Recent → `m18try`: the block design, the top and the settings are as you left them. Then delete `~/m18try` if you like
