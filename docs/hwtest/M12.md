# M12 hardware test: bob's own place and route (M12a)

No RTL change and **no Vivado rebuild**. The M7 bitstream stays in the PL:
- top `bob_top`
- IDCODE `0xABEEF093`
- 4216-bit chain

`hw/build.cfg` stays tagged M7.

Until now VPR placed and routed every guest design. M12a adds **bob's own pack, place and route in Python** (`tools/bob/pnr/`). It works from the same netlist, the same pins and the same committed rr graph, and writes the same result files. FASM, bitgen, `.bit` and every check are shared with the VPR flow. It needs no Docker and runs in well under a second per design.

```sh
./bob build examples/fir.v --pnr python        # instead of VPR
tools/bob/pnr/compare.py                       # both flows side by side -> docs/reports/M12/pnr_vs_vpr.md
```

## How it works

| step | method | reference |
|---|---|---|
| netlist | the eblif `vpr_run.prepare` writes for VPR (constants, carry chains cut to the column, FF buffers, pins) | M9 |
| pack | one BLE per CLB: LUT + the flip-flop it feeds alone, adder + the flip-flop its sum feeds alone; carry chains become macros | VPR pack patterns `ble` / `chain` |
| place | simulated annealing: bounding-box wirelength cost; T0 = 20 × σ of random moves; 10·N^(4/3) moves per temperature; α from the acceptance rate; range limit ×(1 − 0.44 + rate); macros move as a unit up a column; pads fixed | Betz & Rose, VPR placer (FPL 1997) |
| route | PathFinder negotiated congestion with A*, on the committed rr graph; node cost = base × (1 + history) × (1 + present congestion); LUT inputs may land on any free `I` pin (the LUT table is re-indexed) | McMurchie & Ebeling (FPGA 1995); VPR `lut_in` port class |
| output | `.net`, `.place`, `.route` in VPR's formats, then `fasm_from_vpr` → FASM → chain | M9/M10 |

## Result against VPR (`docs/reports/M12/pnr_vs_vpr.md`)

Both flows are measured by the same code from their result files:
- **Every design** uses the same number of CLBs, and both flows' chains match the source on `model.py`.
- **Total wirelength:** VPR 1215, Python 1201 (0.99×). The Python PnR is shorter on `gates`, `switches` and `gates_swapped`, where LUT pin permutation matters because every input pin has only 2 or 4 possible drivers. It is up to 1.17× longer on the carry-heavy designs (`counter`, `fir`), whose adder inputs are fixed to `I[0]`/`I[1]`.
- **Run time:** 0.02–0.17 s per design (pack + place + route), without Docker.

## Proofs before the board (`make check`)

- **`sim/run_cosim_sim.sh`:** 18 designs, every example through VPR *and* through the Python PnR, each loaded from its `.bit` into the complete FPGA RTL. For each, 100 cycles against the source Verilog and the golden netlist: LEDs before and after each edge, and CAPTURE registers. 4618 checks.
- **`tests/test_pnr.py`** checks every example and variant from the written files, independently of the PnR's own bookkeeping:
  - placement is legal (sites, no overlaps, pads where pinned)
  - every routing step is a real mux input, and branches start on their tree
  - no rr node carries two nets
  - every packed sink is reached
  - FASM is legal, and model == source
  - the same seed gives byte-identical files
  - failing cases: too many CLBs, unresolvable congestion, a lone flip-flop
- **`tests/test_hwtest_fake.py`:** the M12 checks pass on the stand-in board, and fail on a wrong CAPTURE.

## Automatic (`make hwtest M=M12`)

The regression runs first: `idcode`, `bypass`, `selftest`, `chain-length` (4216).

| check | you do | pass means |
|---|---|---|
| pnr-gates … pnr-gates-swapped (9) | nothing | the M10 golden check on the **Python-routed** `.bit`: `bob build --pnr python` → `bob load`, readback == FASM, 64 clocks with LEDs == source and CAPTURE == golden registers |
| live-fir-py | follow the guide (same goals as M11 `live-fir`) | the Python-routed FIR live on the real switches: LEDs == model for every stable sample, all goals within 90 s, readback while running == `.bit` |
| live-switches-py | follow the guide (same goals as M11 `live-switches`) | the same for the Python-routed switches.v; runs last and leaves it running |

What the LEDs must show is identical to M11, because the designs are the same and only the routing differs. hwtest prints the guide with example inputs and expected LEDs before each live check and waits for Enter. `make hwtest M=M12 ONLY=live-fir-py` reruns one check.

## By hand (`--manual`)

`switches.v`, routed by the Python PnR, is still running after the automatic checks.

- [ ] switches (Python-routed): LD0 on when exactly one of SW0/SW1 is up; LD1 follows BTN0, and BTN1 only while SW0 is up; each BTN3 press toggles LD2
- [ ] `./bob build examples/blinky.v --pnr python --clock run --div 13 -o build/bit/blinky_py_run.bit`, then `./bob load build/bit/blinky_py_run.bit`: the build prints `pnr python` and a 59.6 Hz clock; on the board LD0 toggles about every 0.54 s and LD2..0 count in binary
