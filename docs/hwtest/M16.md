# M16 hardware test: the 10 × 10 CLB grid

**This milestone needs a Vivado rebuild.** `hw/build.cfg`:
- `tag = M16`
- `top = bob_top`
- `idcode = FBEEF093`  (the last free IDCODE version nibble)
- `usercode = 00000010`

## What changed

Only the device description changed: `tools/bob/device.py` `ARCH_12X10` replaces `ARCH_8X6`. Everything else — the configuration plane, both configuration paths, partial reconfiguration, BRAM content frames, the tools — is the M15 design, regenerated for the bigger grid.

| | M15 (on the board now) | M16 |
|---|---|---|
| VPR grid (with the I/O ring) | 10 × 8 | **14 × 12** |
| core | 8 × 6 | **12 × 10** |
| CLBs | 36 | **100** |
| BRAM / DSP | 2 / 2 (height 3) | 2 / 2 (height 5, columns x = 3 and x = 8) |
| pads | 28 | **44** |
| routing muxes | 1723 | **3391** |
| configuration | 8320 bits = 65 frames | **18 560 bits = 145 frames** |
| K = 4 profile | 6016 = 47 frames | 12 800 = 100 frames |
| boundary cells | 56 | 88 |

**Size, measured before the build** (`tools/bob/synth_estimate.sh`, whole design, yosys):

| | LUT | FF | yosys time | yosys peak |
|---|---|---|---|---|
| M15 (Vivado built it: 5.1 min at 2.0 GB → 10 411 LUT / 11 097 FF, WNS +0.585 ns) | 15 941 | 11 069 | 152 s | 1.36 GB |
| **M16** | **32 891** | **21 485** | 281 s | 2.07 GB |

Scaling by M15's yosys → Vivado ratio, expect roughly **21 k LUTs (≈ 40% of the XC7Z020)** and **≈ 21.5 k FFs (≈ 20%)**. That fits, but this is the first build where synthesis is clearly bigger than M15's five minutes, and the loop-breaking phase grows with the routing muxes (1723 → 3391).

**If the machine struggles** (it restarted once under load at M13): say so and we drop to an 8 × 8 core (64 CLBs), which is about half this growth. Close other programs first; `jobs = 1` in `hw/build.cfg` makes implementation gentler.

The rules that made M13 and M15 build are unchanged: no computed part-select over the configuration memory, no `keep_hierarchy`, and the XDC is used in implementation only.

## New example: `examples/big.v`

A 24-bit LFSR and a 16-bit counter, **56 CLBs** — it cannot fit the 36-CLB grid at all. BTN0 steps both, BTN1 resets them, and the LEDs mix the parity of the LFSR, the parity of the counter and the two switches, so every register reaches an output. It goes through the same checks as every other example: yosys equivalence (300 cycles), VPR and bob's PnR, FASM legality, `model.py` against the source trace, golden co-simulation, and on the board LEDs == source with CAPTURE == golden.

## Proofs before the build (`make check`, `make mutate`)

- Every testbench passes on the 100-CLB fabric: `tb_bob` 852, `tb_frames` 71, `tb_clock_gap` 11, `tb_cfg` 180, `tb_synth` 972, `tb_cosim` (now 11 designs × 2 flows), `tb_clb`/`tb_bram`/`tb_dsp`, and the K = 4 fabric.
- VPR routes all 11 examples on the new graph; bob's PnR does too (`make pnr`).
- All three mutation suites pass. `sim/mutate_fabric.sh`'s `carry-direct-cut` now cuts the carry of **column 12** (the last CLB column, `designs.FULL_COL_X`).
- Fixed while resizing (real bugs, not just numbers):
  - `tb_bob` used `` `CNT8_BITS `` above the `include` of `vectors.vh`: iverilog did not complain and the comparison register came out 2 bits wide, failing 298 checks. The comparison registers are plain 32-bit now.
  - The CAPTURE check compared 64-bit values; CAPTURE is 100 bits on this grid.
  - `CNT8_MASK` carried a fixed `8'h` width; it now matches the column height (10 bits).
  - The frame testbench's stream vector (16 384 bits) was too small for a 145-frame load stream; `SW` is 40 960 in `sim/gen_frame_vectors.py` and `hw/tb/tb_frames.v` (they must match).
  - `test_blinky_chain_crosses_columns` proved the M8 placer splits a carry chain across columns. With 10-row columns blinky fits one column, so the test uses `wide` and also checks each piece occupies contiguous rows.

## Build (Windows)

1. Replace `E:\bob_full_v1\hw` with this `hw/` and run `build.tcl`.
2. Program the board and copy the whole `bob_vivado\out\M16\` folder to `docs/reports/M16/`.
3. On the Mac run `make check` (it requires timing closure and the single-cycle registers in `sysclk_1cycle.txt`).
4. If Vivado stops or the PC restarts, send `bob_vivado\bob.runs\synth_1\runme.log` (or `impl_1\runme.log`) and say which happened.

## Automatic (`make hwtest M=M16`)

The full M15 list on the new bitstream — the regression (idcode `0xFBEEF093`, bypass, selftest, the M7 fabric checks through the chain with **chain-length 18560**, the five frame checks, the guest designs as frames, ram-readback, blinky-rate), `bob-wide` / `pnr-wide`, the four partial-reconfiguration checks and the three BRAM-frame checks — plus:

| check | pass means |
|---|---|
| bob-big | `examples/big.v` (56 CLBs, impossible on the old grid) through VPR: every user clock the LEDs equal the source's and CAPTURE equals the golden netlist's 40 registers |
| pnr-big | the same design through bob's own place and route |

`pipeline-live` runs last and leaves the pipeline on the switches.

## By hand (`--manual`)

- [ ] After `make hwtest M=M16`: SW1..0 = 00 lights LD0, 01 lights LD1, 10 lights LD2, 11 lights all three (the pipeline, as at M7)
- [ ] `./bob build examples/big.v --clock run --div 17 -o build/bit/big_run.bit`, then `./bob load build/bit/big_run.bit`: with BTN0 held the LEDs flicker (the LFSR parity changes every step); releasing BTN0 freezes them; BTN1 resets to the seed (LD2 off, LD1 off, LD0 shows the seed parity)
- [ ] Partial reconfiguration still works on the big grid: `./bob build examples/gates.v -o build/bit/gates.bit`, `./bob load build/bit/gates.bit`, then `./bob build examples/gates.v --pcf examples/gates_swapped.pcf -o build/bit/gates_swapped.bit` and `./bob load --partial build/bit/gates_swapped.bit`. It prints how many of the 145 frames it rewrote; with all buttons released, SW0 up and SW1 down, the LEDs go from LD1 + LD2 lit to only LD1 lit.
