# M24 hardware test: Double Duty elements (the adder beside a LUT)

**This milestone needs a Vivado rebuild.** `hw/build.cfg`:
- `tag = M24`
- `top = bob_top`
- `idcode = 0B024093`
- `usercode = 00000018` (24)
- `delays = 1`

## What changed

Pun, Dai, Zgheib, Iyer, Boutros, Betz and Abdelfattah, *Double Duty: FPGA Architecture to
Enable Concurrent LUT and Adder Chain Usage* (FPL 2025, arXiv 2507.11709): in an AMD- or
Intel-style logic element the adder reads its operands through the LUT, so an adder bit uses
the whole element. They route some of the element's inputs straight to the adder, which
leaves the LUT free for other logic.

In bob (`hw/src/clb/ble.sv`), a new element flag `dd` (with `cy_en`) does this:
- The adder reads A = `in[K-2]` (also the carry's generate input) and B = `in[K-1]`
  directly: propagate = A ^ B ^ INV_B, where INV_B for subtraction is `cy_di_sel`, unused
  in this mode.
- The LUT is free. Its O5 half drives `out[1]` (optionally through the second flip-flop)
  as a LUT(K-2) over `in[K-3:0]`.
- The paper bypasses 4 inputs into an ALM's 2 adders. bob's element has one adder, so it
  bypasses 2.

VPR's element gets a `dd` mode in place of the old `arithmetic` mode, and bob's own
packer fills each adder element's free LUT. Packed logic elements over the examples, against
M23 (`docs/reports/M24/`):

| packer | M23 | M24 | change |
|---|---|---|---|
| VPR | 295 | 281 | −4.7% (wide −14%, bd_demo −17%, fir16 −5%) |
| bob's Python PnR | — | 256 | −13.2% against M23's VPR (big −26%, wide −33%, fir −33%, atspeed −16%, fir16 −8%) |

The grid is unchanged: 10 × 10 CLBs, 68,096 bits. Host cost: +120 LUTs (+0.5%), 400 flip-flops.

## Size before the build

`software/bob/synth_estimate.sh`: 25,811 logic LUTs (M23 25,691) + 12,800 CFGLUT5 + 23,239
configuration flip-flops. Vivado should land near M23: about 36.8k LUTs, slices about 88%.

## Build (Windows)

1. Replace `E:\bob_full_v1\hw` with this `hw/` (from the `bob_full_v1_m24` worktree) and
   run `build.tcl`.
2. Program the board. Copy **the files** of `bob_vivado\out\M24\` (not the folder) into
   `docs/reports/M24/`: `bob_top.bit`, `timing.rpt`, `util.rpt`, `drc.rpt`,
   `build_info.txt`, `sysclk_1cycle.txt`, `delay_paths.rpt`. The folder already holds
   `pnr_vs_vpr.md`; replacing the whole folder would delete it.
3. On the Mac: `software/bob/delays.py fold docs/reports/M24/delay_paths.rpt`, then
   `make check`.

## Automatic (`make hwtest M=M24`), about 10 minutes

The full M23 list runs first. It now includes the new `dd` design in the self-test, and the
VPR- and Python-built examples (bob-/pnr-fir16, big, wide) whose elements now use Double
Duty. Then:

| check | pass means |
|---|---|
| double-duty | In clb(2,2), element 0's adder takes SW0 + SW1 on its bypass inputs (LD0 = sum) and element 1 passes the carry (LD1 = SW0 AND SW1). Element 0's own LUT computes BTN0 AND SW0 beside the adder (LD2). All 8 inputs match a hand-written truth table, loaded as frames and over the chain. |

## By hand (`--manual`), about 5 minutes

- [ ] Load the dd design: `software/host/fpga.py --load dd`. SW0 up → LD0 on. SW0 and SW1 up → LD0 off, LD1 on. SW0 up and hold BTN0 → LD2 on as well.
- [ ] live-fir16 as before: SW0 up, hold **BTN0**: the LEDs settle in about two seconds and hold after you release.
