# M15 hardware test: M12b + M14 + M15 in one build

One Vivado build carries three milestones. **This milestone needs a Vivado rebuild.** `hw/build.cfg`:
- `tag = M15`
- `top = bob_top`
- `idcode = EBEEF093`
- `usercode = 0000000F`

| milestone | what | IDCODE nibble |
|---|---|---|
| M12b | smaller configuration store (the chain streamed through one frame buffer) paying for an **8×6 grid: 36 CLBs** (was 16), 28 pads, 65 frames = 8320 bits | (C, not built alone) |
| M14 | **partial reconfiguration** of a running design: AGHIGH freezes the user clock, only the changed frames are written, LFRM releases after the CRC | (D, not built alone) |
| M15 | **BRAM contents as frames** (FAR block type 001): configuration and contents in one CRC-covered stream | **E** |

## What changed

### M12b: area, then a bigger grid

**Where the area went** (yosys, M13): `cfg_store` 5 106 LUTs + 9 984 FFs and `cfg_frames` 2 649 LUTs, i.e. half the design was configuration bookkeeping. The chain kept a full 4 992-bit shift register beside the 4 992-bit memory, with a data mux per bit.

**The change** (`hw/src/core/cfg_store.v`, `docs/bitstream-format.md` section 4):
- One 128-bit frame buffer instead of the W-bit shift register. CHAIN_IN streams: every 128th bit writes a frame (only while GWE = 0). CHAIN_OUT reloads the next frame every 128 bits.
- One frame-wide read mux shared by CHAIN_OUT and FDRO (M13 had a separate 156-way word mux for FDRO).
- A bad chain CRC now leaves the new bits in memory but COMMITTED stays 0, so JSTART refuses. This is exactly how frames already behaved (UG470). A running design is never written.
- Chain length is measured with a repeated marker: after the memory, CHAIN_OUT is a 128-bit delay line.
- Store + controller: 7 755 → 4 104 LUTs, 10 309 → 5 469 FFs (yosys).

**The grid** (`tools/bob/device.py` `ARCH_8X6`): 8×6 core, BRAM column x=3 and DSP column x=6 at height 3 (2 of each, as before), W = 24, 36 CLBs, 28 pads. VPR re-generated the rr graph; every example was re-routed by VPR and by the Python PnR (wirelength 1 304 vs VPR 1 405, `docs/reports/M12b/pnr_vs_vpr.md`). New example `examples/wide.v` (12-bit counter + 8-bit LFSR) packs into **31 CLBs**, more than the old grid had.

**Why Vivado should not crash** (every earlier crash was synthesis):

| | LUTs | FFs | yosys time | yosys memory |
|---|---|---|---|---|
| M13 RTL (Vivado built it: synthesis 3.5 min, 2.0 GB; implementation 2.5 GB) | 15 358 | 12 220 | 143 s | 1.04 GB |
| **M15 RTL** | **15 941** (+3.8%) | **11 069** (−9.4%) | 152 s | 1.36 GB |

- The logic is the same size as M13's.
- The XDC stays out of synthesis (the M13 crash fix), and there is no `keep_hierarchy`.
- The 48-CLB profile that took 30+ minutes at M7 was synthesised *with* the XDC loop breaking.

### M14: partial reconfiguration (`docs/bitstream-format.md` section 12)

- `cfg_frames.v`:
  - **AGHIGH** (UG470 CMD 8) raises `freeze`, which needs the IDCODE match.
  - `clock_ctrl.v` holds `gce` low and acknowledges.
  - STAT bit 7 **GHIGH_B** = 0 once the acknowledgement is back in the TCK domain.
  - Frames may then be written with GWE = 1.
  - **LFRM** releases the freeze only after a CRC match; otherwise the fabric stays frozen with the error in STAT.
- Every fabric register (CLB flip-flops, BRAM, DSP) is enabled only by gce, so the whole design's state is kept exactly.
- **Host:**
  - `packets.partial_streams(old, new)` writes only the changed frames.
  - `cfgplane.load_partial` reads the current memory over CHAIN_OUT, freezes and checks GHIGH_B = 0, writes the frames, then checks GHIGH_B = 1 and the readback.
  - `bob load --partial x.bit` runs it.

### M15: BRAM contents as frames (`docs/bitstream-format.md` section 13)

- FAR block type `001`: column = BRAM, frame n (0..255) = addresses 4n..4n+3, word = `{14'b0, data}`.
- FDRI (GWE = 0 only) hands each frame to `bram_jtag.v`'s sysclk side, which writes it through the port USER4 uses.
- FDRO reads frames back; the controller prefetches each frame.
- `bob load` (frames) now sends every word of every BRAM the design uses **inside the load stream**, under its CRC, and reads them back over FDRO. `bob load --mode chain` still uses USER4.
- STAT version `0x15`.

## Proofs before the build (`make check`, `make mutate`)

- **`tb_frames`, 71 checks** (was 34), all expectations from `packets.Controller`:
  - **[13] partial reconfiguration:**
    - a free-running counter + an AND gate
    - AGHIGH → STAT GHIGH_B = 0 → no gce pulse in 400 ns and none during the whole partial write
    - 1 frame rewritten → the counter continues from its frozen value, LD1 is now OR, STAT released
  - [14] no CRC → LFRM refused, stays frozen
  - [15] AGHIGH without IDCODE refused
  - [16] bad CRC → stays frozen
  - [17] frames before the freeze is acknowledged → WR_ERROR
  - [18] BRAM frames into bram0, crossing into bram1 by FAR auto-increment; FDRO readback
  - [19] BRAM frames while running refused
- **`tb_clock_gap`, 11 checks:** [4] no gce while frozen (both clock modes, with step requests); frozen and gce never together; pulses resume after release.
- **Earlier testbenches:** `tb_bob` (852), `tb_cfg` (180), `tb_synth` (972), `tb_cosim` (5 220, now with `wide`), K=4 (722) all pass on the 36-CLB fabric.
- **`sim/mutate_frames.sh`: 34 mutants, all killed.** New: 3 for the streamed store, 5 for M14 (freeze ignored, LFRM ignores CRC, frames without the acknowledgement, AGHIGH without IDCODE, GHIGH_B stuck), 5 for M15.
- **Stand-in board:** passing and failing cases for every new check (a board that loses state on a partial, one whose freeze does not hold, one that writes BRAM frames while running). Fixed on the way: it never modelled USER1 `cin`, and its free-running clock ignored INTEST pads.

## Build (Windows)

1. Replace `E:\bob_full_v1\hw` with this `hw/` and run `build.tcl`. It rebuilds (the generated fabric and the core changed).
   - **During synthesis**, close other programs. The yosys estimate says it is M13-sized; expect roughly the same 3–5 minutes.
   - **If the PC struggles:** set `jobs = 1` in `hw/build.cfg` first.
2. Program the board and copy the whole `bob_vivado\out\M15\` folder to `docs/reports/M15/`.
3. On the Mac, run `make check`. It requires timing closure and the single-cycle registers in `sysclk_1cycle.txt`.
4. **If Vivado stops:** send `bob_vivado\bob.runs\synth_1\runme.log` (or `impl_1\runme.log`), and say whether Windows restarted.

## Automatic (`make hwtest M=M15`)

**Regression:** idcode (`0xEBEEF093`), bypass, selftest, then every M13 check on the new bitstream:
- the M7 fabric checks through the chain (chain-length now 8320)
- the 5 frame checks
- bob-gates / counter / ram / mult / fir, pnr-switches
- ram-readback, blinky-rate

**New:**

| check | pass means |
|---|---|
| bob-wide | the 31-CLB design through VPR: LEDs == source, CAPTURE == golden (20 registers) |
| pnr-wide | the same through the Python PnR |
| partial-swap | JTAG-stepped counter + AND; 5 clocks; `load_partial` to OR rewrites 1 frame; counter still 5, LD1 now OR; 3 more clocks → 8 |
| partial-live | free-running counter (~3.7 counts/s) moving; AGHIGH → GHIGH_B = 0 and the counter stands still for 1.2 s; frames + LFRM → GHIGH_B = 1 and it counts again; LD1 now OR |
| partial-bad-crc | a partial with a wrong CRC: refused, CRC_ERROR, GHIGH_B = 0, the counter stands still, DONE stays; JPROGRAM + full load counts again |
| partial-guest | `bob load` gates, `bob load --partial` gates_swapped: only the changed frames, LEDs == gates_swapped |
| frames-bram-load | ROM design + random contents in both BRAMs in one stream: FDRO readback == contents, USER4 reads the same words, ROM LEDs == mem[SW] |
| frames-bram-live-refused | BRAM frames while running: WR_ERROR; after JPROGRAM the contents are unchanged |
| ram-readback-frames | ram.v writes its BRAM through 64 clocks; after JPROGRAM, FDRO block type 1 == model.py == USER4 |

`pipeline-live` still runs last and leaves the pipeline on the switches.

## By hand (`--manual`)

- [ ] After `make hwtest M=M15`: SW1..0 = 00 lights LD0, 01 lights LD1, 10 lights LD2, 11 lights all three (the pipeline, as at M7)
- [ ] Partial reconfiguration you can see.
  - **Load gates:** `./bob build examples/gates.v -o build/bit/gates.bit`, then `./bob load build/bit/gates.bit`. With all buttons released, SW0 up and SW1 down: **LD1 and LD2 on**, LD0 off.
  - **Partial:** `./bob build examples/gates.v --pcf examples/gates_swapped.pcf -o build/bit/gates_swapped.bit`, then `./bob load --partial build/bit/gates_swapped.bit`. It prints how many frames it rewrote. Same switches: **only LD1 on** (inputs and outputs are swapped).
- [ ] `./bob load build/bit/gates.bit --mode chain` still loads; the same switches light LD1 and LD2 again
- [ ] `tools/bob/packets.py dump build/bit/gates.bit | head -30` shows sync, RCRC, IDCODE EBEEF093, FAR, WCFG, FDRI type-2 count 260
