# M22 hardware test: LUT contents in CFGLUT5, 9 × 9 CLBs

**This milestone needs a Vivado rebuild.** `hw/build.cfg`:
- `tag = M22`
- `top = bob_top`
- `idcode = 0B022093`
- `usercode = 00000016` (22)
- `delays = 1`: the element and crossbar delays change (CFGLUT5 trees), so time them again
  (`hw/scripts/delay_samples.txt`, 1100 hops)

## What changed

**Each element's truth table and each crossbar mux live in AMD CFGLUT5 primitives**
(UG953, a LUT5 whose table is shifted in). They used to be configuration flip-flops plus
a big multiplexer. Measured in yosys, a CLB went from 469 LUTs + 424 configuration
flip-flops to 193 LUTs + 48 flip-flops. That room buys a bigger grid:

| | M21 | M22 |
|---|---|---|
| CLBs | 49 (7 × 7) | **81 (9 × 9)** |
| LUTs | 196 | **324** |
| configuration | 32,896 bits, 257 frames | 56,448 bits, 441 frames; 30,456 bits held only in CFGLUT5s |
| pads | 32 | 40 |
| BRAM / DSP | 2 / 2 | 2 / 2 (columns 4 rows tall) |
| CAPTURE | 392 bits | 648 bits |

- **Nothing on the wire changes.** The same frames, CRC, FASM, partial reconfiguration and
  BRAM content frames. Readback still comes from the M21 BRAM shadow.
- **Loading:** `lut_loader.v` shifts each written frame into the CFGLUT5s of the CLB that
  owns it over 32 TCK cycles, while the next frame arrives. JPROGRAM sweeps zeros into
  every table (a dark fabric), and JSTART waits for the loader.
- **The CFGLUT5s need SLICEM slices.** 81 CLBs × 152 = about 12.3k of the chip's 17.4k
  SLICEM LUTs (71%).

## Size before the build

`software/bob/synth_estimate.sh` (yosys, whole design):

| | logic LUTs | CFGLUT5 | FFs | yosys peak |
|---|---|---|---|---|
| M21 (Vivado: 36,450 LUT / 36,308 FF) | 58,535 | 0 | 35,995 | 6.3 GB |
| **M22** | **36,980** | **12,312** | **25,449** | 5.1 GB |

Projected in Vivado: **35k-42k LUTs (66-79%)**, SLICEM about 71%. That's fuller than M21,
so implementation may take longer. If placement or routing fails for lack of slices, the
grid steps down to 9 × 8 CLBs (one number in `software/bob/device.py`; `HANDOFF.md` §0).

- If placement fails on SLICEM ("not enough sites" for LUTs as memory / shift registers),
  send `runme.log`: the fix is one number in `device.py` (a smaller grid).
- The two `place_report:` lines in `runme.log` (about 15 minutes in) must both show a
  positive WNS. If one is negative by more than a few ns, stop the run and send
  `runme.log` and `impl_1\bob_top_timing_placed.rpt`.

## Build (Windows)

1. Replace `E:\bob_full_v1\hw` with this `hw/` and run `build.tcl`.
2. Program the board, then copy the **whole** `bob_vivado\out\M22\` folder to
   `docs/reports/M22/` (timing, utilization, DRC, `sysclk_1cycle.txt`, `delay_paths.rpt`).
3. On the Mac, in the M22 checkout:
   ```sh
   software/bob/delays.py fold docs/reports/M22/delay_paths.rpt
   make check
   ```

## Automatic (`make hwtest M=M22`), about 35 minutes

It runs the full M21 list first, on the new fabric: every configuration path, partial
reconfiguration (whose rewrites now land in CFGLUT5s), the BRAM frames, the block designs,
the waveform checks, the four clock checks and the cluster checks. Then the new one:

| check | pass means |
|---|---|
| lutram-snake | SW0 → all 324 logic elements in one combinational chain → LD0, each a buffer or an inverter from a random mask. It's loaded over frames, then its complement over the chain. LD0 = SW0 xor the mask's parity for both switch positions both times: every truth table and crossbar tree loaded |

## By hand (`--manual`), about 10 minutes

The M21 steps, on the bigger fabric:

- [ ] live-fir16: put SW0 up and hold **BTN0**. The LEDs settle to a steady pattern in about two seconds. Release BTN0: the LEDs hold.
- [ ] Hold **BTN1**: every LED goes off.
- [ ] In the studio (`./bob studio --probe usb`), open `work/examples/fir16/fir16.v` and **Generate Bitstream**. The Device view shows the 9 × 9 grid of CLBs, each with its four element cells.
- [ ] `./bob build work/examples/big/big.v --clock run --hz auto -o build/bit/big.bit`: the timing line shows the critical path.
