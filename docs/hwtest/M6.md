# M6 hardware test: complete FPGA + DSP tile

Build: `hw/build.cfg` has `tag = M6`, `top = fpga4x4_top`, `idcode = 8BEEF093`, `usercode = 00000006`. This is the complete FPGA: M5 plus a **DSP tile** on the fabric's North edge, two cascaded DSP48E1-style slices (UG479 trimmed). The chain is now 3720 bits.

1. Replace `E:\bob_full_v1\hw` and run `build.tcl` (it rebuilds).
2. Program the board, copy `bob_vivado\out\M6\` to `docs/reports/M6/`, then run `make check`. **The report checks now also require `util.rpt` to show DSPs ≥ 1**, alongside the RAMB18.
3. `timing.rpt`: WNS ≥ 0 (M4 was only +0.84 ns: send `timing.rpt` if M6 is negative), and no "No valid object" warnings for the `u_dsp` multicycle exceptions.

## Automatic (`make hwtest M=M6`)

Regression first: `idcode` (`0x8BEEF093`), `bypass`, `selftest`.

Then the earlier milestones' checks:
- usercode (6), chain-length (3720)
- ir-status, crc-reject-live, gts, gsr-gwe, capture-user1, jprogram, showcase-live
- ce-sr, counter-step, counter-run
- bram-init, bram-locked, bram-rom, bram-modes

Then M6:

| check | pass means |
|---|---|
| dsp-modes | 3 configuration pairs × 20 operations, every bus and control driven over the private DSP instruction, one clock per USER1 step. Covers M, M+C, P+M, (PCIN>>17)+M, pre-adder D+A and D−A, and every register stage. P0 and P1 match `model.py` through the cascade |
| dsp-mult | combinational multiplier through the fabric: INTEST {SW1,SW0} = 0..3, B = 3, LD2..0 = product[2:0] |
| dsp-accum | P ← P + A·B on the free-running clock (div 16), A = B = 1: P grows 6–9 per second (7.45 expected) |
| dsp-accum-live | leaves the accumulator running |
