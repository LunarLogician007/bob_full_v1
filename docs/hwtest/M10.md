# M10 hardware test: `bob build` / `bob load`, golden LEDs and CAPTURE

No RTL change and **no Vivado rebuild**. The M7 bitstream stays in the PL:
- top `bob_top`
- IDCODE `0xABEEF093`
- 4216-bit chain

`hw/build.cfg` stays tagged M7.

## What M10 adds

**`./bob build design.v [--pcf pins.pcf] [--clock jtag|run --div N]`** (`tools/bob/cli.py`) runs these steps, each checked before the next:
1. Synthesis: yosys onto bob cells.
2. Equivalence: source == yosys netlist == **golden netlist** (`tools/bob/golden.py`: the same netlist with every net named), over 300 cycles in iverilog. Every golden net's value after each clock is saved.
3. VPR: a committed result in `tools/bob/vpr/<name>/` is reused if it was routed from this netlist, pins and architecture; otherwise VPR runs in Docker.
4. FASM, legal against `device.json`.
5. Chain (`tools/bob/bitgen.py`): chain → FASM → chain is exact.
6. `model.py` == source trace.
7. `.bit` (chain file version 2): chain, CRC, BRAM contents, META, file CRC.

**`./bob load x.bit`** loads the design onto the board:
1. JPROGRAM, then CFG_IN.
2. Status and CFG_OUT readback.
3. BRAM contents over USER4.
4. JSTART, then DONE.

Other commands: `./bob info x.bit` and `./bob fasm x.bit`.

**Pin files:** a `.pcf` has `set_io <port> <SW0|SW1|BTN0..3|LD0..2|pad<N>>` lines. `examples/gates_swapped.pcf` swaps SW0/SW1 and reverses the LEDs.

## Proofs before the board (`make check`)

**`sim/run_cosim_sim.sh`** is the golden co-simulation. Each of the 7 designs is built by `bob build` and loaded from its `.bit` into the complete FPGA RTL through CFG_IN. It then runs 100 fresh random cycles against:
- the **source Verilog, live** (not a recorded trace)
- the golden netlist

Before and after every edge, the fabric LEDs must equal the source's and the golden netlist's. After every edge, CAPTURE must read every CLB flip-flop equal to the golden register.

The testbench was mutation-checked. Each of these fails it:
- a wrong golden net
- a CRC-valid routing change
- a missing source clock
- unswapped pins
- dropped BRAM contents
- a wrong golden LUT

**Tests:**
- `tests/test_bitgen.py`:
  - random and VPR chain → FASM → chain round trips
  - bad FASM and tail bits refused
  - `.bit` v2 corruption caught; v1 still reads
  - pcf parsing
  - the swapped-pins check isn't vacuous
- `tests/test_hwtest_fake.py`: the M10 board check runs against a software stand-in board (`model.py` behind the JTAG instructions). It passes on a good board and fails on a wrong CAPTURE, so scan order and bit indexing are right before your board run.

## Automatic (`make hwtest M=M10`)

The regression runs first: `idcode`, `bypass`, `selftest`, `chain-length` (4216).

Each `bob-*` check:
1. `bob build` → `build/bit/<name>.bit`
2. `bob load` without JSTART; CFG_OUT readback is decoded to FASM and must equal the `.bit`'s FASM
3. JSTART
4. For 64 clocks (USER1 autostep, one clock per INTEST scan):
   - CAPTURE after each clock: every CLB flip-flop == golden netlist register
   - LEDs after each clock == source Verilog

| check | design | registers on CAPTURE |
|---|---|---|
| bob-gates | 3 LUTs | 0 |
| bob-adder | carry chain | 0 |
| bob-counter | 6-bit counter, CE/SR | 6 |
| bob-blinky | 8-bit counter, 15 CLBs | 8 |
| bob-ram | BRAM, contents from the `.bit` | 0 |
| bob-mult | DSP multiplier | 7 |
| bob-gates-swapped | gates.v through `gates_swapped.pcf` | 0 |

## By hand (`--manual`)

- [ ] Pins: with only SW0 up (buttons released), `./bob load build/bit/gates.bit` lights LD1 and LD2, and `./bob load build/bit/gates_swapped.bit` lights only LD1 (SW0 is `sw[1]` there, and `led[2]` lands on LD0)
- [ ] `./bob build examples/blinky.v --clock run --div 13 -o build/bit/blinky_run.bit && ./bob load build/bit/blinky_run.bit`: 125 MHz / 2^21 ≈ 60 Hz user clock; LD0 (q[5]) toggles about every 0.54 s, and LD2..LD0 count in binary
