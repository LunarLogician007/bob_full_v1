# M26 hardware test: INIT apart from the reset value, TDO high impedance outside Shift

**This milestone needs a Vivado rebuild.** `hw/build.cfg`:
- `tag = M26`
- `top = bob_top`
- `idcode = 0B026093`
- `usercode = 0000001A` (26)

## What changed

**INIT and SRVAL are two bits** (UG474: an FDRE or FDSE has INIT, the value GSR loads, and
a reset value, SRVAL, the value its synchronous reset loads; they are independent). Until
M25, bob's flip-flop had one bit, `ff_rstval`, for both, so a design with
`reg q = 1'b1;` and a reset to 0 came up at 0 after configuration.

- `device.py`: each element gets `ff_init` and `ff2_init` (element fields 13 and 14). The
  chain stays at 68 096 bits, 532 frames: the two bits per element fit in the padding.
- `ble.sv`: GSR (startup and UG470 GRESTORE) loads `ff_init` / `ff2_init`. SR still loads
  `ff_rstval` / `ff2_rstval`.
- Flow: yosys keeps the register's own init (`dfflegalize ... 01`, `bob_map.v`); VPR and
  bob's Python placer carry it into `ff_init`; `model.py` starts from it. A design that sets
  no init starts at its reset value, as before. A flip-flop with a constant D
  (`if (rst) q <= 0; else if (en) q <= 1;`) now goes through VPR too.
- New example `work/examples/initval/initval.v`: an FDRE that starts at 1, an FDSE that
  starts at 0, a plain register that starts at 1.
- Time-travel restores (`snapshot.py`) now write the snapshot into INIT only, and a
  restored design's resets keep their own values.

**TDO is high impedance outside Shift-IR / Shift-DR** (IEEE 1149.1). `jtag_tap6.v` has a
`tdo_oe`, updated on the falling edge of TCK with TDO. Both tops drive the pin through an
OBUFT.

**TMS / TDI input delays are referred to TCK's falling edge** (`-clock_fall` in the XDC).
The probe changes them while TCK is low, so they have half a period to reach the rising
edge, not a whole one. At 1 MHz that is 500 ns against 20 ns of input delay.

## Watch in runme.log

- Both `place_report:` lines: WNS positive for sysclk and for tck.
- `report_utilization`: slices should stay close to M25 (86.8%). Each element's
  configuration grew by two bits: about 800 more configuration flip-flops on the
  whole fabric.
- `tdo` in the IO report: an OBUFT. The tristate is written in `bob_fpga.v` and reaches
  the port through `bob_top.v`; if Vivado warns that it cannot push it to the port, send
  `runme.log`.

## Build (Windows)

1. Replace `E:\bob_full_v1\hw` with this `hw/` (from the `m26` worktree) and run
   `build.tcl`.
2. Program the board. Copy **the files** of `bob_vivado\out\M26\` (not the folder) into
   `docs/reports/M26/`, including `delay_paths.rpt`.

## Automatic (`make hwtest M=M26`), about 13 minutes

The full M25 list runs first (every earlier check, with the new IDCODE). Then:

| check | pass means |
|---|---|
| init-srval | One CLB, CE on SW0, SR on SW1. Element 0: INIT 1, SRVAL 0, D 1. Element 1: INIT 0, SRVAL 1, D 0. Right after startup LD1..0 = 01 (the INITs); SR gives 10 (the SRVALs); CE gives 01 (the Ds), every step against `model.py`. A pre-M26 fabric reads 10 at startup. |
| bob-initval | `initval.v` through yosys, VPR, FASM and `bob load`: every user clock the LEDs equal the source's and CAPTURE equals the netlist's registers, starting from the INITs. |
| pnr-initval | The same through bob's own Python place and route. |

## By hand (`--manual`), about 5 minutes

- [ ] `./bob build work/examples/initval/initval.v --clock run -o build/bit/initval_run.bit`, then `./bob load build/bit/initval_run.bit`: **LD0 lit, LD1 dark, LD2 lit.** (A pre-M26 fabric shows LD0 dark, LD1 lit.)
- [ ] Press BTN0: LD0 goes dark and LD1 lights (both resets). Release: they stay.
- [ ] Press BTN1: LD0 lights. Press BTN2: LD1 goes dark.
- [ ] SW0 down, press BTN3: LD2 goes dark. SW0 up, press BTN3: LD2 lights.
- [ ] Press BTN0 again (LD0 dark, LD1 lit), then `./bob load build/bit/initval_run.bit` once more: back to LD0 lit, LD1 dark, LD2 lit.
- [ ] `./bob snap save s`, press BTN0, then `./bob snap restore s`: the LEDs return to the pattern saved in `s`.
