# Chapter 04: Routing

*wires in channels, the switch and connection boxes, and the bits that choose*

Running time 4.3 min. Generated by the render of `scenes/ch04_*.py`; edit the scene, not this file.

Routing is most of an FPGA's area, and most of bob's. This chapter follows a signal from a pin, along the wires, through the boxes that join them, to another block.

Between every row and column of tiles runs a channel of wires: 36 tracks wide in bob. Horizontal wires are called CHANX and vertical ones CHANY, VPR's names.

Each wire is 4 tiles long, so a signal crosses the chip in a few hops instead of one per tile. And each wire is unidirectional: it has exactly one driver, a multiplexer at the end where it starts. Some wires run east or north, others west or south.

Where a horizontal and a vertical channel cross sits a switch box. A wire that ends there can continue straight on, or turn left or right: three choices, which is what Fs equals three means.

Because wires are unidirectional, the box is really a set of multiplexers: each wire leaving it is driven by a mux whose inputs are the wires arriving. The Wilton pattern changes the track number when a signal turns, so that the network mixes well.

Blocks connect to the channels through connection boxes. A block input pin is a multiplexer too, but it can only reach a fraction of the tracks: with fc in equal to nought point one, about four of the thirty-six.

Its select value zero means constant zero, one means constant one, and from two upwards it picks a track. Outputs work the other way round: a block output pin appears as an input on the muxes of a tenth of the tracks beside it.

Every routing multiplexer in bob uses one encoding. Value zero is constant zero. On block input pins value one is constant one. After that the drivers follow in ascending node number, and any value past the last driver also reads zero.

The choice of zero matters more than it looks. A configuration of all zeros connects nothing to anything, so it cannot contain a combinational loop. The fabric powers up dark and safe, and JPROGRAM returns it to exactly that state.

Most routing muxes are small: two to twelve drivers. The tall bar on the right is the crossbars. Every one of the twenty-four element inputs in each of the hundred blocks chooses among twenty-four sources.

Inside the host, each routing mux is now built by hand from AMD primitives. Four-input slices of the mux are LUT6s on the two low select bits. Two of those meet in a MUXF7, and two of those in a MUXF8. A sixteen-way mux fills exactly one slice.

Left to itself, synthesis had spent nearly a whole LUT on each small mux. Building them from primitives cut the routing's host LUTs by about thirty percent, and together with the crossbar change it made room for the ten by ten grid.

Here is a real route from the counter example. The reset button, btn one, enters at a pad on the west edge, at x zero, y four. Its destination is a logic block at x seven, y three, where the counter lives.

VPR chose 5 wires: down the west channel, east along the bottom on three consecutive length-four wires, then up into the block. Each hop is one multiplexer, and its configuration value selects the hop before it.

And this is the price of building an FPGA out of another one. A single routing hop costs up to 4.6 nanoseconds, because it is a host LUT, a MUXF7 and real host wiring. These three numbers were measured on the routed host design; the LUT, carry and flip-flop figures are still estimates.

VPR now routes using these delays, and chapter six shows how bob turns them into a safe clock for every design.

The mux cell is written by hand and checked against its old behavioural table at every width; every instance is generated; and the fabric testbench routes random netlists and compares every output with the model after every clock.
