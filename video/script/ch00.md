# Chapter 00: An FPGA inside an FPGA

*what bob is, the machines it runs on, and how it was built*

Running time 3.5 min. Generated by the render of `scenes/ch00_*.py`; edit the scene, not this file.

This film explains bob from A to Z. bob is a complete, programmable FPGA, written in Verilog, that runs inside a real FPGA. Every number you will see is read from the repository itself, at milestone M26.

There are two FPGAs in this project, and keeping them apart is the first thing to understand. The host is real silicon: a Xilinx XC7Z020 on a PYNQ-Z2 board.

The guest is bob. It is our own fabric of logic blocks, memories, multipliers and routing, written in Verilog and compiled by Vivado into the host.

Vivado, on a Windows machine, programs the host once, with a bitstream called bob_top.bit. After that the host never changes.

The guest is programmed as often as you like. A Mac runs bob's own tools, and sends the guest's configuration over USB to a Raspberry Pi Pico, which speaks JTAG to the guest's own configuration port.

So whenever something is confusing, ask whose bitstream it is. The host's bitstream is made by Vivado and changes only when bob's hardware changes. The guest's bitstream is made by bob's own tool chain from your Verilog, and it is loaded over JTAG every time you build a design.

Here is the guest, drawn from its own device description. A ring of 44 I/O pads surrounds a ten by ten array of logic blocks, with one column of block RAM and one column of DSP slices cut into it.

That is 100 configurable logic blocks holding 400 six-input lookup tables, 2 block RAMs and 2 DSP slices. Everything is set by 68,096 configuration bits, organised as 532 frames.

bob is built in five layers. The architecture is one Python file, device.py, and it is the only place where architecture numbers live. The hardware is generated from it. The configuration layer is the memory that holds the guest's bits and the controller that fills it. The tools turn a design into those bits, and the host software loads them and checks the result on the board.

This one rule holds the project together. Growing the grid from 16 to 36 to 100 logic blocks was an edit to one dictionary and two commands.

The project was built in twenty seven milestones, from M0 to M26, and no milestone was closed by simulation alone. Each one ended with a hardware test on the board, which also re-ran every earlier milestone's checks.

The pieces came first, then a fabric generated from the router's own graph, then the tool flow, AMD-style configuration frames, the cluster logic block, and the largest grid this chip can hold. The last run, M26, passed 74 of 74 checks.

The chapters follow the layers. First what an FPGA is, and how bob's architecture is described as data. Then the logic block, the routing, the memories and multipliers, the pads and the clock. Then JTAG, the configuration memory, the scan chain and the frame protocol. And finally how a design becomes a bitstream, and how all of it was verified.
