# M4 hardware test: complete FPGA + user clock, routed CE/SR, LUT size K

Build: `hw/build.cfg` has `tag = M4`, `top = fpga4x4_top`, `idcode = 6BEEF093`, `usercode = 00000004`. This is the complete FPGA:
- the fabric, now with 191-bit tiles because of routed CE/SR (LUT K=6 on the board)
- a clock-control tile at the head of the chain, so the chain is 3064 bits
- the board's 125 MHz **sysclk on H16** driving the fabric through a clock enable
- the M2/M3 configuration plane and boundary scan

1. Replace `E:\bob_full_v1\hw` and run `build.tcl`. It rebuilds, because the sources, XDC and `bob_params.vh` changed.
2. Program the board, then copy `bob_vivado\out\M4\` to `docs/reports/M4/`, then run `make check` (report checks).
3. In `timing.rpt`, confirm:
   - there are two clocks (`tck`, `sysclk`) and they are asynchronous
   - WNS is non-negative
   - the multicycle exceptions matched cells (no "No valid object" critical warnings; `make check` catches that)

LEDs: LD2..LD0 = `pad_o`, LD3 = DONE.

## Automatic (`make hwtest M=M4`)

Regression first: `idcode` (`0x6BEEF093`), `bypass`, `selftest` (all 11 designs).

Then everything M3 checked, on the new build:
- usercode (4)
- chain-length (3064)
- ir-status
- crc-reject-live
- gts
- gsr-gwe
- capture-user1
- jprogram
- showcase-live

Then M4:

| check | pass means |
|---|---|
| ce-sr | `designs.d_ce_sr`: CE routed from the SW0 path, SR from the SW1 path, driven via INTEST. Load (CE), clear (SR beats CE, and SR works with CE low), hold; all 7 steps match `model.py` |
| counter-step | 4-bit carry-chain counter, JTAG-stepped: each 16-bit CAPTURE scan is 21 TCK edges, so the count steps by exactly 5 (mod 16) every scan; with USER1 ce off it stays constant |
| counter-run | free-running, `clk_div` 16: 125 MHz / 2²⁴ = 7.45 counts/s, measured over ~3 s (pass 6–9/s), independent of TCK |
| blinky | leaves the counter free-running at `clk_div` 17 for the LED check below |
