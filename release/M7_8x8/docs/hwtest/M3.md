# M3 hardware test: the complete 4×4 FPGA on the configuration plane

Build: `hw/build.cfg` has `tag = M3`, `top = fpga4x4_top`, `idcode = 5BEEF093`, `usercode = 00000003`. This is the **complete FPGA**: fabric, boundary scan and the M2 configuration plane.

1. Replace `E:\bob_full_v1\hw` and run `build.tcl`. Top and sources changed, so it rebuilds.
2. Program the board, then copy `bob_vivado\out\M3\` to `docs/reports/M3/`.
3. Record LUTs/FFs from `util.rpt` next to M0's (4271 LUTs, 5910 FFs). Expect roughly +2900 FFs for the shadow registers.

LEDs: LD2..LD0 = `pad_o`, **LD3 = DONE** (configured, CRC checked, startup complete).

## Automatic (`make hwtest M=M3`)

Regression first (complete FPGA):

| check | pass means |
|---|---|
| idcode | `0x5BEEF093` through the 6-bit TAP |
| bypass | 1 bit |
| selftest | all 11 designs load through JPROGRAM/CRC/CFG_IN/readback/JSTART and match the model through INTEST |

Then M3:

| check | pass means |
|---|---|
| usercode | `0x00000003` |
| chain-length | a CFG_OUT marker comes out after exactly 2896 bits; config unchanged; showcase still correct |
| ir-status | after a load: DONE, INIT_B, COMMITTED in the IR capture |
| crc-reject-live | a corrupted chain while showcase runs: CRC_ERR, DONE stays, showcase config kept and still correct |
| gts | committed but not started: outputs 000; after JSTART: showcase's answer |
| gsr-gwe | registered tile (INIT 1, D 0): reads 1 under GSR, 0 once JSTART releases GSR and asserts GWE |
| capture-user1 | CAPTURE (16 CLB outputs) equals USER1 status [19:4] |
| jprogram | config cleared, outputs 000, DONE off |
| showcase-live | showcase reloaded; real LEDs equal the model for the current switches |

## By hand (`--manual`)

- [ ] After `make hwtest M=M3`, showcase is running: LD3 on, SW0/SW1 give AND on LD0, OR on LD1, XOR on LD2
